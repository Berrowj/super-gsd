Super GSD · SGSD1 / SGSD2 / SGSD3 Dashboards

Three reactive PowerShell dashboards (v5) that sit beside the Claude Code session and turn .planning/ state into a live cockpit. Each uses a FileSystemWatcher so panes repaint only when source files change — no polling flicker. Together they answer the three questions a human needs to stay oriented: where am I, what is Claude doing, is it good enough to ship?

SGSD1 · P3

sgsd-mission-control.ps1 — Mission Control

super-gsd/scripts/sgsd-mission-control.ps1

What it shows

  • Milestone header with progress bar parsed from ROADMAP.md (handles **bold** markdown).
  • Phase progression strip: last built · current · next with full ROADMAP traceability.
  • Wave timeline for the active phase, each wave stamped with its git completion time.
  • Red counters for remaining phases and sub-waves so slippage is visible at a glance.
  • Session cost box — Opus / Sonnet / Haiku token spend, total, and per-phase roll-up.
  • Agent roster showing ACTIVE / IDLE / RECENT status per sub-agent.
  • Context-% gauge, thinking-mode indicator, blocker list, checkpoint banner, recent commits.
How it helps you understand the project: it is the project map. At any moment you can see how far along the milestone is, which phase the orchestrator has its hands in right now, what already shipped, and what is still ahead — plus the cost of getting here. If you walked in cold, this single pane tells you the size, shape, and burn rate of the work.
SGSD2 · P4

sgsd-narrative.ps1 — Narrative + Ctrl+O Stream

super-gsd/scripts/sgsd-narrative.ps1

What it shows

  • Top pane — a cached Haiku-generated narrative (paragraph + bullets) describing what Claude is currently doing. Regenerates every 5 minutes and only when activity has actually changed, so it is cheap on tokens.
  • Bottom pane — live Ctrl+O-style tool stream tailed from the active Claude session JSONL (~/.claude/projects/<cwd>/<session>.jsonl). Every tool_use and tool_result scrolls past in real time.
How it helps you understand the project: Mission Control tells you where you are; Narrative tells you what is happening right now. The Haiku summary translates raw tool traffic into plain English ("currently editing the phase-8 verifier, waiting on a lint run") while the stream underneath lets you drill into the exact calls. Great for onboarding — read the top pane to grasp intent, watch the bottom pane to learn the mechanics of how the orchestrator actually works.
SGSD3 · P5

sgsd-gate-verdict.ps1 — Gate Verdict Board

super-gsd/scripts/sgsd-gate-verdict.ps1

What it shows

Quality-gate status for the active phase, reading:

SourceSurfaces as
STATE.mdCurrent phase pointer
{NN}-VERIFICATION.mdVerifier verdict card
{NN}-ATC-REVIEW.mdATC verdict (Karpathy receipts)
{NN}-BROWSER-REVIEW.mdBrowser-verify verdict
BACKEND-NOT-READY.mdGate 4 halt evidence
TOOL-FALLBACK.mdGate 1 fallback declaration
evidence/, screenshots/Artifact counts
DEFERRAL-LEDGER.mdOpen deferrals

Also renders an enforcement block, phase timeline, Nyquist + Security gate cards, and a gate-history trend line.

How it helps you understand the project: this is the ship / don't ship board. It converts scattered review artifacts into a single verdict view so you can see instantly whether the current phase cleared its gates, which artifacts are still missing, and whether anything was deferred. If Mission Control is the map and Narrative is the live camera, Gate Verdict is the flight recorder + control tower telling you whether the approach is safe.

Using them together

  • SGSD1 — strategic view (where we are in the milestone).
  • SGSD2 — tactical view (what Claude is doing this minute).
  • SGSD3 — quality view (is the current phase actually done).

Run all three in adjacent panes (tmux / Windows Terminal split) and you get a complete, zero-polling cockpit over the autonomous loop — the same information the orchestrator itself reasons about, surfaced for a human observer.
