The P150 Ceremonies, Explained Simply

Why three tasks in this phase need you at the keyboard — and what each one actually does. 2026-08-09.

The verdict in one sentence: everything this milestone built is sitting safely on your machine, and the three ceremonies are the deliberately human-only steps that publish it (T150-05), grant Codex trust and prove the guard-rail really fires (T150-06), and repeat that safely on devcp (T150-07) — with every step designed to stop rather than guess.

ELI5 — the house-keys analogy

Imagine SGSD just had a new security system installed in two houses — your PC and the devcp server. The installers (Codex, under review) did all the wiring. But three things no installer is allowed to do:

  1. Move the furniture in (T150-05): the new equipment is boxed up in your workshop (the feature branch). Someone with the master key has to carry it into the real house (push to GitHub master, update your live install). The ceremony script is a moving checklist that refuses to move anything if a box looks tampered with.
  2. Turn the key the first time (T150-06): the alarm system won't arm until the homeowner personally turns the key once. That's the Codex trust prompt — there is intentionally no way for a robot to click "trust" for you. Then, crucially, you test the alarm by trying the forbidden door: a real Codex dispatch attempts to write a forbidden file, and the ceremony only passes if the alarm log shows a brand-new "blocked!" entry from that exact attempt. An old alarm entry doesn't count — that would be like trusting last year's fire-drill.
  3. Do the second house (T150-07): same key-turning and alarm-testing at devcp — but that house has 883 boxes of old private letters in the attic (the PII fork history). The ceremony photographs the attic first and guarantees not one box is thrown out or mailed anywhere.

Why can't the loop do this itself?

Observed Three hard reasons, not politeness:

  • Codex trust is interactive by design. Trust state lives in ~/.codex/state_5.sqlite and the CLI offers no legitimate grant command — only the interactive prompt. The one bypass flag that exists is exactly the thing this phase forbids using.
  • Publishing is irreversible and outward-facing. Pushing to GitHub master propagates to every SGSD install. The reviews caught real ways this could go wrong (a repointed remote, a sneaky second push URL), so a human confirms while the script enforces.
  • devcp holds un-pushable history. Its fork carries commits with your real name and emails. Any automated "sync" that guessed wrong could publish them. The ceremony's job is to make that structurally impossible.

What you actually type

T150-05 — Publish

Observed One PowerShell block from PROPAGATION.md § Local propagation, run from the cholla-racer feature branch. Paste it; it stops and asks you once:

Read-Host 'Coordinate users of the local
master worktree, then type FAST-FORWARD'

Everything else is automatic-but-paranoid: it throws (stops dead) on a dirty tree, wrong branch, wrong origin URL, wrong push URL (all of them, not just the first), or any outgoing commit not authored by the generic operator identity.

T150-06 — Local trust

Observed Three short blocks from § Trust ceremony:

codex -C $p150LocalRepo   # approve hooks
# then: install-hooks + self-test
# then: the forbidden-write probe

The probe is the heart: it notes where the alarm ledger ends before dispatch, has Codex genuinely attempt secrets\p150-trust-probe.env, and demands a freshly-appended block / forbidden_path row after that offset. Then sgsd-local-restart-evidence.ps1 -Phase Prepare, restart your terminals/MCP, -Phase Finalize.

T150-07 — devcp

Observed SSH to devcp and run the § devcp propagation blocks: safety checks (no running sessions, clean state), fresh backup, guarded --ff-only update of ~/.claude/super-gsd/source, the same trust ceremony, then sgsd-devcp-restart-evidence.sh for tmux/MCP/cockpit identity JSON.

Inferred This is the slowest of the three — budget 20–30 minutes with the coordination checks.

Failure modes — what to do if it stops

It throws with a message. That's the design — every stop names the exact check. Paste the error to Claude; nothing destructive has happened, because all guards run before their action.
The Codex trust prompt never appears. Hooks may already be trusted from an earlier session — the probe is still valid proof either way; run it.
Nothing here is one-way until the final push. The publish is the only irreversible step, and it's the last thing T150-05 does, behind every other gate.
