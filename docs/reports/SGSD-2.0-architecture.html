SGSD 2.0 — Orchestration Architecture

A problem enters through one router, gets classified into one of four paths (strategic debate / build / audit / inline), and is handed to a specialized engine with its own model routing, evidence gates, and atomic-commit discipline. The engines share a common substrate: a git-native memory store and five MCP knowledge sources that get queried mid-flight. Every decision and learning becomes a durable artifact the next run can cite.
