Phase map: click a phase

The milestone is a pipeline. It starts by measuring waste, then builds the smaller context machinery, then routes work, then proves the result.

How the machinery connects

1. Measure

Phase 41 and 42 say where tokens go and when spend is unhealthy.

2. Compress

Phase 43 turns closed phases into small capsules instead of folders to reread.

3. Validate

Phase 44 creates legal IDs so packets cannot invent phases, gates, agents, or artifacts.

4. Compile

Phase 45 converts messy operator English into explicit intent and a tiny role packet.

5. Prove

Phases 46-52 retrieve, route, govern, display, benchmark, and optionally cache live state.

Dependency chain

ELI5: what each phase is, as a normal object

41 = the electricity meter

It tells us which agent is burning tokens, instead of guessing from vibes.

42 = the spending limit

It says: this role should not need a giant context unless there is a logged reason.

43 = chapter summaries

At phase close, SGSD writes a capsule so future work reads the summary, not every page.

44 = the official dictionary

It lists valid phases, gates, agents, statuses, and artifacts so fake names get rejected.

45 = the lunchbox packer

It turns your command into clear intent, then packs only what the current agent needs.

46 = the library index

It lets SGSD search summaries and decisions fast without making the index the source of truth.

47 = the traffic controller

It decides whether local script, Codex, Claude, or VTP should handle a task.

48 = the specialist library pass

It calls VTP only when books, papers, prior memory, or architecture challenge are truly needed.

49 = the librarian rules

It controls what becomes memory, what gets revoked, and how complaints repair packets.

50 = the control room

It redesigns the cockpit so you can see current phase, active agents, token spend, and context mix.

51 = the exam

It stress-tests before vs after and must prove token reduction without losing evidence.

52 = sticky notes on the desk

Redis can speed live views and hot packets, but if it disappears, the truth remains safe.

The truth ladder: what owns reality?

v1.9 is careful about memory. It does not let a cache or index become the truth. The truth stays in files, phase artifacts, JSONL ledgers, and git commits.

Canonical truth

.planning files, JSONL metrics, phase artifacts, reviews, debt ledgers, git commits.

Capsules

Machine-readable summaries built from canonical truth, with hashes and references.

Indexes

SQLite and query helpers for fast source-backed retrieval. Rebuildable at any time.

Packets

Small role-specific prompts assembled from capsules, registry, index, and critical raw evidence.

Redis

Optional hot cache for live state, counters, active markers, and packet previews.

What must never happen

Redis or SQLite becomes the only place where a decision exists.
A critical error, stack trace, security issue, or provider outage gets summarized away.
The packet builder accepts an invented phase, gate, agent, or artifact ID.
VTP is called just because words sound semantically related.
Token budgets silently overrun without a warning, degrade row, or reroute reason.
The benchmark passes by hiding evidence or telling the model it is a benchmark.

Where Redis fits

Redis is useful for live speed

Use it like a whiteboard beside the desk: current phase, active agents, hot packets, provider canary cache, live token counters.

Live cockpit state Hot context packets Provider health cache Short-lived counters

Redis is not the fix by itself

If SGSD stores giant context in Redis and pastes it back into prompts, token spend stays bad. Redis only helps after packets and capsules exist.

Not canonical memory Not a markdown dump bucket Not required for SGSD to run Not allowed to hide data loss

Close checklist
