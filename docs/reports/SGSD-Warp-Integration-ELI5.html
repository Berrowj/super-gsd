How Warp agents help SGSD

There are two useful agent modes: third-party CLI agents like Claude/Codex running in Warp, and Warp's own agent asking questions about the live terminal and SGSD files.

Claude Code inside Warp

Use Claude for SGSD orchestration, planning, phase work, and repository edits. Warp gives it a better terminal home.

Codex inside Warp

Use Codex for independent review, ATC checks, code quality, and adversarial critique.

Warp agent

Use Warp agent for operator questions, live terminal inspection, workflows, MCP calls, and recovery support.

Ask this

"What is SGSD doing right now, and is it actually progressing?"

Warp should query

sgsd.current_state, sgsd.watchdog_status, sgsd.current_phase, sgsd.latest_commits

Good answer

"v2.0 P53 is active. Researcher is running. Last durable progress was 3 minutes ago. No hard blocker. Next artifact expected: 53-RESEARCH.md."

Can Warp run Bash and PowerShell without you being the middle man?

Yes. Warp is the terminal. The trick is to run the SGSD commands inside Warp from the start, then save them as workflows.

PowerShell

Run SGSD boot, cockpit, watchdog, and resume commands directly in Warp's PowerShell session.

cd C:\Users\user\GSDedits
powershell -NoProfile -ExecutionPolicy Bypass -File .\super-gsd\scripts\sgsd-boot.ps1

Bash

SGSD already uses Git-Bash internally where needed. Warp can run Bash commands if your shell/profile supports Git-Bash or you invoke it explicitly.

& "C:\Program Files\Git\usr\bin\bash.exe" -lc "git status --short"
Important: Warp will not control old PowerShell windows outside Warp. The win is to start the cockpit, Claude, Codex, and watchdog from Warp so Warp is the single operator surface.

What this does not magically mean

This is where we keep expectations sharp so we do not waste another day chasing the wrong layer.

Not instant native cockpit panels

Warp can host terminal panes now. Custom first-class GUI panels likely require Warp client work, a plugin/extension surface if one exists, or upstream contribution.

Not a replacement for SGSD

Warp is the operator shell. SGSD remains the autonomous delivery engine, with gates, memory, phase capsules, and watchdog.

Not a reason to copy AGPL code

Study Warp's architecture, integrate via public features, and be careful before copying client code into SGSD.

Not all agents are free

Warp's own agent/model usage depends on Warp plan/model setup. But workflows, terminal hosting, and third-party CLI agents still help immediately.
