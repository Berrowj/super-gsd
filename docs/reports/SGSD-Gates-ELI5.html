SGSD gate system, explained like you are five

Every gate is a tiny airport checkpoint.

SGSD is a workflow for getting AI agents to do serious work without drifting, rushing, hiding mistakes, or filling the repo with junk. A gate is a small checkpoint that asks: "Is it safe and useful to let this work move to the next runway?"

The control tower idea

A plane does not fly because one person says "looks fine." It gets checked by radar, ground crew, maintenance, runway control, and air traffic control. SGSD does the same for agent work.

The Simple Rule

Each gate has five parts. If you can understand these five words, you can understand the whole SGSD safety system.

Trigger

When does the checkpoint wake up? Example: "code files changed" or "phase diff is big."

Check

What does it inspect? Example: architecture risk, waste, missing evidence, stale context.

Evidence

What receipt does it leave behind? Good gates write artifacts, not vibes.

Escalation

What happens if something is wrong? Soft warning, replan, hard halt, or phase block.

ELI5

Imagine building with Lego. A gate is the grown-up who checks: "Is this piece in the right place? Did we use too many pieces? Did we forget the wheels? Did we write down what we changed?"

What VTP added

VTP is the library brain: books, papers, prior decisions, and research distilled into practical rules. The VTP audit changed the gate philosophy from "add more checkpoints" to "make existing checkpoints actually load-bearing."

In practical terms: every useful signal should be consumed downstream, critical findings should change the path, and every enrichment call should be logged as success, zero hits, disabled, timeout, or error.

Where The Gates Sit

SGSD gates are spread through the workflow. Early gates choose direction, middle gates protect implementation, late gates verify and learn.

Code Quality Gates

These are the airport maintenance checks. They ask whether the code itself is safe, coherent, and not becoming accidental spaghetti.

per-dispatch-ATC

hard halt step 9.5 Codex reviewer

Like checking one plane before takeoff. If an agent changes code and the task looks risky, ATC reviews that specific dispatch before it gets treated as safe.

When
When the classifier says ATC tier is full or gate, and code files changed.
Does
Runs the ATC review checklist, anti-slop checks, and complexity pressure on the changed work.
Catches
Bad architecture, hidden complexity, sloppy fixes, risky shortcuts, weak contracts, and code that "works" but makes the system worse.
Benefit
Stops one bad dispatch from contaminating the phase. It is the fast local safety net.
VTP enrichment VTP pushed this from advisory review toward load-bearing review. The audit removed the idea that critical ATC findings can silently bypass in auto mode: critical means fix, replan, gap-plan, or block.

phase-level-ATC

amortized halts on critical step 6.5

Like checking the whole airport day, not just one plane. It asks whether all the work in the phase makes sense together.

When
At phase close, after verification passes and before the phase is marked complete.
Does
Reviews plans, commits, summaries, and the phase as one coherent unit.
Catches
Cross-plan contradictions, drift, duplicated architecture, phase-wide complexity creep, and "each part is okay but the whole is messy."
Benefit
Protects the shape of the system, not just individual changes.
VTP enrichment VTP's architecture-fitness pattern changed this gate from log-only to halt-on-critical. The key lesson: final success can hide internal breakdown, so a critical phase review must alter the path.

Process Hygiene Gates

These are the gates that keep the AI workflow clean: right task, right context, no waste, learn from mistakes, and do not burn tokens blindly.

classifier-haiku

soft warnstep 2

Like asking "what kind of job is this?" before grabbing tools.

When
At the start of orchestration.
Does
Classifies complexity, ATC tier, deliberation need, and likely workflow path.
Catches
Trivial work being over-processed, risky work being under-reviewed, and planning tasks being treated like coding tasks.
Benefit
Prevents the wrong workflow from starting. Cheap Haiku routing saves expensive downstream correction.
VTP enrichment VTP reinforced cheap structural routing first: use fast signals before expensive agents or reviews.

context-selector-haiku

soft warnstep 4

Like packing the right backpack: not every book, only the ones needed for this trip.

When
After classification, before agents start using context.
Does
Selects relevant planning, memory, and code context for the next agent.
Catches
Context bloat, missing key files, stale assumptions, and accidental over-reading.
Benefit
Improves answer quality while keeping token cost and context drift under control.
VTP enrichment HCC and Experience Compression pushed this toward tiered memory: promote useful context, avoid raw context dumping.

sgsd-recall-queries

soft warnstep 5

Like asking "have we made this mistake before?" before doing the same thing again.

When
When the classifier says the task is not trivial.
Does
Searches prior SGSD lessons, anti-patterns, and memories that might apply.
Catches
Repeated mistakes, already-ruled-out paths, stale patterns, and lessons hidden in old phases.
Benefit
Makes SGSD compound. Every phase can improve the next one.
VTP enrichment Thought Retriever and HCC pushed recall toward validated, provenance-backed lessons instead of vague memory stuffing.

intent-injection

soft warnstep 5.5

Like pinning the teacher's instruction on the desk so nobody forgets the assignment.

When
Before execution prompts are dispatched.
Does
Keeps the user's actual goal and constraints visible inside the agent context.
Catches
Scope drift, agents solving nearby-but-wrong problems, and summaries that lose the original intent.
Benefit
Prevents "technically did work" from becoming "did the wrong work."
VTP enrichment WLS highlighted context decay: important intent must survive across stages, not live only in the opening prompt.

MUDA-waste-audit

soft warnstep 6.555 probes

Like checking the workshop floor for mess: broken tools, waiting around, wasted walking, too many half-finished things.

When
At phase close when enough files or diff lines changed, except docs/config/refactor-only phases.
Does
Runs five probes: haiku failures, stale narrative, git-spawn rate, extra-processing, and inventory.
Catches
Silent model failures, stuck refresh loops, N+1 git waste, over/under review patterns, and stale scratch/draft/temp artifacts.
Benefit
Keeps process waste visible before it becomes normal.
VTP enrichment The VTP audit found the old design emitted five probes but only consumed three. It was fixed so all five now flow through WASTE.md, metrics, curation, and recurrence. Inventory was recalibrated so old canonical phase docs are not falsely treated as waste.

qualitative-waste-audit

soft warnstep 6.55Codex

Like asking a human-looking inspector: "Did we build anything nobody asked for?"

When
For larger non-doc/config phases, usually when diff lines are at least 200 and mechanical MUDA is not already failing hard.
Does
Uses a reviewer to spot soft waste: YAGNI, duplication, over-engineering, defensive code with no failure mode, and orphan work.
Catches
Waste that numbers alone miss, especially overproduction and unnecessary complexity.
Benefit
Stops "busy" from being confused with "useful."
VTP enrichment Skill-RAG and TACO shaped this: diagnose the failure type before retrying or adding machinery.

sgsd-curate-learnings

soft warnstep 10

Like putting a good lesson into the class rulebook after someone learns the hard way.

When
When a new pattern, script, or error is discovered.
Does
Turns raw discoveries into reusable SGSD memory or anti-pattern entries.
Catches
Knowledge evaporating after a phase, repeated debugging, and lessons trapped in chat logs.
Benefit
Makes the workflow self-improving instead of amnesiac.
VTP enrichment VTP pushed lifecycle governance: provenance, confidence, novelty, usage, expiry, and dead-end labels.

token-log

soft warnstep 11

Like a fuel gauge. The plane may still fly, but you need to know how much fuel it burned.

When
After agent/reviewer activity that should be costed.
Does
Logs estimated input, output, provider, model, role, elapsed time, and token totals.
Catches
Expensive rituals, runaway review loops, and hidden cost regressions.
Benefit
Lets SGSD retire or tune process that costs more than it earns.
VTP enrichment Think Just Enough shaped the policy: spend compute where uncertainty and risk justify it, not everywhere.

Verification Completeness Gates

These gates check the checker. They exist because a verification report can look official while its math or detail is wrong.

verifier-row-arithmetic

soft warnverify-mjs

Like counting the stickers on a homework chart and making sure the total is real.

When
When a phase has a verification script/report.
Does
Checks that row counts, pass/fail totals, and summary numbers agree.
Catches
Arithmetic mistakes, impossible pass rates, and summaries that do not match raw verification rows.
Benefit
Makes verification auditable instead of decorative.
VTP enrichment WLS emphasized raw artifact evaluation: trust the row math, not only the final claim.

verifier-detail-vs-summary

soft warnverify-mjs

Like checking that the report card comments match the actual test answers.

When
When a phase has detailed verification evidence and a summary.
Does
Compares detailed rows against the headline summary.
Catches
False green summaries, hidden failed checks, missing detail, and optimistic close-out text.
Benefit
Prevents "looks verified" from replacing actual verification.
VTP enrichment VTP evidence warned that superficial success can mask internal breakdown; this gate keeps the details load-bearing.

The VTP Enrichment Gate

This is the planned Phase 21 gate: it turns VTP from a passive library into an active checkpoint between research and planning.

vtp-enrichment

plannedresearch to planVTP corpus

Like asking the library teacher: "Before we start building, do any books or past lessons say we are missing something?"

When
After phase research and before planning, when config.json.vtp_enrichment.enabled is true.
Does
Queries VTP using the phase domain, requirement acceptance criteria, and research findings. Writes VTP-ENRICHMENT.md.
Catches
Known patterns from books/papers, missing alternatives, prior project lessons, zero-hit areas, and library contradictions.
Benefit
Stops SGSD from planning in isolation. The planner starts with external memory already attached.
VTP enrichment VTP enriched its own gate design: calls should be thresholded, empty hits are valid evidence, errors are different from zero hits, and every exit path must be logged.

edge-guard ledger

gate ledgerfitness function

Like the clipboard that records which checkpoints opened, which stayed shut, and why.

When
Whenever a gate is evaluated or an expected artifact is missing.
Does
Logs gate id, expected evidence, missing emits, resolution, and whether the system should halt or continue.
Catches
Silent skip drift: a gate that everyone thinks is active but is not actually producing receipts.
Benefit
Makes the gate system itself auditable.
VTP enrichment Fundamentals of Software Architecture pushed this toward fitness functions: each gate needs objective proof that it fired, passed, skipped validly, or halted.

The VTP Upgrade In One Sentence Per Gate

The big enrichment was not "add more process." It was "make every gate earn its keep."

ATC

Critical architecture risks cannot silently pass into phase completion.

MUDA

Every emitted waste probe must be consumed by audit, recurrence, and summary.

Verifier

Every failed verifier result needs a fix, gap-plan, or recorded deviation.

VTP

Every enrichment call records whether evidence was used, rejected, empty, unavailable, or failed.

Memory

Every promoted memory needs provenance, confidence, usage, and expiry.

Board

Every role must contribute distinct information or be redesigned.

Token

Context and review cost must trigger compression or pruning before failure.

Edge Guard

The gate system needs receipts for its own behavior.
