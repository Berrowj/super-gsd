Output 2 — SGSD handover design rules

Practical rules for Chronicle HTML. Each: rule, source book(s), reason, SGSD example, implementation suggestion.

Rule 01 — Lead with the operator decision

Minto SwD  Image00085 p.5 · 0.79 · storytelling-with-data ::0255

Reason: The reader must never reconstruct the conclusion from the evidence. Minto: top-down ordering is "the single most important act in clear writing." SwD: a one-sentence Big Idea anchors everything.

SGSD example: A fixed Operator Decision Panel at the top: phase verdict (PASS / PASS-WITH-DEFERRED / BLOCKED), validator verdict (REPORT_GROUNDED), confidence, files changed count, open risks count, ONE recommended next action.

Implementation: New <section role="operator-decision"> rendered first, above all evidence. Every field is a cited projection — the verdict comes from VERIFICATION.md, not prose.

Rule 02 — Section headings are testable governing statements

Minto SwD  Image00080 p.108 · 0.63 · storytelling-with-data ::0132 · 0.74

Reason: Minto: a governing thought must be a testable, idea-rich assertion, not a vague label. SwD: takeaway titles carry the "so what?".

SGSD example: Not "Validator Output" but "Validator caught 2 ungrounded claims — both re-cited and re-validated". Not "Risks" but "1 unresolved risk: plantuml.jar still absent on the build host".

Implementation: Section-template {{heading}} slot becomes a cited synthesis node — filled from CMB evidence, validated like any claim. Empty evidence → MISSING_EVIDENCE → REPORT_UNGROUNDED.

Rule 03 — Frame "why this phase existed" as Situation → Complication → Question

Minto  Image00201 p.202 · 0.68 · Image00190 p.191 · 0.67

Reason: The Situation anchors the reader in something they already accept; the Complication creates genuine tension; the Question is what the phase answered.

SGSD example: S: "v3.0 shipped the mesh substrate." C: "But the operator still went brain-foggy after long autonomous runs." Q: "How does SGSD explain a phase well enough to keep the operator attached?" A: the phase deliverable.

Implementation: why-phase-existed.md template gains explicit {{situation}} {{complication}} {{question}} slots, each cited to CONTEXT.md / INTENT.md. Complication slot is optional — omit for routine phases (no fake drama).

Rule 04 — One recommended next action, alternatives one fold down

Stick  made-to-stick ::0160 · 0.71 · ::0170 · 0.70

Reason: Decision paralysis: a menu of choices produces operator inaction. Relentless prioritisation beats it.

SGSD example: "Next: install plantuml.jar, then re-run P115 render." — not "Options: (a) install jar (b) skip_gates (c) defer (d) …".

Implementation: "What happens next" renders exactly one primary action prominently; the roadmap-miner's alternatives go in a collapsed <details>Other paths considered</details>.

Rule 05 — Every claim is a one-click testable credential

Stick  made-to-stick ::0103 · 0.65 · ::0179 · 0.64

Reason: "See for yourself" — a falsifiable, reader-verifiable claim beats assertion. A cited CMB ID / file path / commit SHA IS a testable credential.

SGSD example: Each claim node's citation renders as an inline expandable showing the CMB body excerpt + a copy-able git show <sha> / file path.

Implementation: render-html.cjs wraps every citations[] entry in <details class="evidence"> with the resolved excerpt inline. Validator's REPORT_BROKEN_CITATION already guarantees the credential resolves.

Rule 06 — Pair every metric with its one telling instance

Stick  made-to-stick ::0108 · 0.63

Reason: "A few vivid details may be more persuasive than a barrage of statistics." A number alone is inert.

SGSD example: Fog Score panel: "Fog 58 / medium — driven mostly by 4 plan revisions; the recurring one was the Codex stale-schema-shape fix."

Implementation: fog-score.cjs already returns a breakdown; the renderer surfaces the top-1 contributing signal as a plain-language sentence beside the number.

Rule 07 — Collapse, never delete; declutter by default-folding

SwD  storytelling-with-data ::0102 · 0.71

Reason: Removing low-signal elements makes the signal stand out — but a chronicle is an audit artefact, so hidden ≠ gone.

SGSD example: Raw-evidence appendix, full lineage DAG, and the PUML source blocks render inside <details> collapsed by default; the validator still parses the hidden content.

Implementation: render-html.cjs marks sections signal: high|low; low-signal sections emit collapsed. Fog Score high → auto-expand the must-read sections.

Rule 08 — Spell the "So What?" in text — the chronicle has no presenter

SwD  book_figures c06f002 · 0.64 · storytelling-with-data ::0189 · 0.70

Reason: Written reports (unlike live presentations) cannot rely on a speaker to deliver the takeaway — the text must carry it.

SGSD example: Every diagram gets a one-line caption stating the conclusion ("Gate waterfall: all 8 gates green except chronicle-validation, which is the phase you are reading").

Implementation: Each PUML render is wrapped with a mandatory <figcaption> takeaway slot; empty caption → MISSING_EVIDENCE.

Rule 09 — Match the diagram type to the question type

Napkin  the-back-of-the-napkin ::0067 · 0.77 · ::0069 · 0.67

Reason: The <6><6> model: who/what→portrait, how-much→chart, where→map, when→timeline, how→flowchart, why→plot. Question type dictates diagram type.

SGSD example: "What changed" → file-impact map (portrait of what). "When did stages run" → timeline. "How did evidence flow" → lineage-dag flowchart. "How did gates progress" → gate-waterfall flowchart.

Implementation: Document the question→diagram mapping in the P115 template README; reject a 7th diagram unless it answers a question the existing 6 don't.

Rule 10 — Make the layout mirror the logic

Minto SwD  Image00048 p.49 · 0.76 · storytelling-with-data ::0097 · 0.71

Reason: The eye reads structure before content; readers zig-zag from top-left. Indentation and heading levels must equal logical nesting.

SGSD example: Heading level = signifier nesting depth. Reading key (what this section proves) sits top-left of each panel; evidence sits below-right.

Implementation: style.css heading scale strictly tied to section depth; no decorative heading sizes. Panel grid: title row top-left-aligned.

Rule 11 — Write against the Curse of Knowledge — the Chronicle Writer IS the cursed expert

Stick  made-to-stick ::0013 · 0.68 · ::0074 · 0.69

Reason: The Writer runs with full phase context; left free it escalates to abstraction (exactly the engineers' "increasingly elaborate drawings" failure).

SGSD example: ELI5 template forbids: CMB-class names, schema keyword jargon, internal acronyms — unless first defined inline.

Implementation: A validator lint pass — CHRONICLE-JARGON warning — flags ELI5/synthesis sections containing un-expanded internal terms from a denylist (CMB, SAC, ATC, MUDA, signifier_role…).

Rule 12 — Tune diagrams to an execution-oriented operator (SQVID)

Napkin  the-back-of-the-napkin ::0055 · 0.70

Reason: SQVID as a graphic equalizer — a technical execution audience wants Quantity + Execution + Comparison, not Vision + Simple abstractions.

SGSD example: Diagrams show concrete counts, real repo paths, before/after deltas — keep exactly one Vision-level diagram (architecture) for orientation.

Implementation: Already largely true (file-impact, gate-waterfall are execution-skewed). Document the SQVID setting in the P115 README so future diagrams stay tuned.

Output 3 — Recommended HTML section order

Top-down (Minto): conclusion first, support beneath, appendix last. Declutter (SwD): low-signal sections collapsed by default. The order below is the proposed canonical chronicle layout.

1 · Operator Decision Panel Minto SwD

Purpose: Answer-first. The operator gets verdict + next action in 5 seconds.

Contains: phase verdict · validator verdict · confidence · files-changed count · open-risk count · one-sentence Big Idea · one recommended next action.

Must NOT contain: evidence detail, narrative, agent prose. Every field is a cited projection.

Helps the operator: decide in seconds whether they need to read further at all.

2 · Why this phase existed (S-C-Q) Minto

Purpose: Orient the reader in known ground, then the tension, then the question answered.

Contains: Situation (cited to predecessor SUMMARY) · Complication (optional, cited to CONTEXT/INTENT) · Question.

Must NOT contain: the answer (that is the rest of the document) or manufactured drama.

Helps the operator: rebuild the mental model of why this work happened.

3 · What changed (ELI5) Stick

Purpose: Plain-language summary that defeats the Curse of Knowledge.

Contains: concrete prose — files, behaviour change, the one most important change + its citation.

Must NOT contain: un-expanded internal jargon, schema keywords, CMB-class names.

Helps the operator: understand the change without decoding the substrate.

4 · What was verified · What reviewers claimed · What was refuted Stick Minto

Purpose: The evidence spine — testable credentials. MECE: observations / claims / evidence-verdicts kept separate.

Contains: claim nodes, each with one-click citations to CMB IDs / tests / commits.

Must NOT contain: uncited claims (→ REPORT_UNGROUNDED), validator self-report taken on trust.

Helps the operator: trust the verdict by spot-checking any claim themselves.

5 · Key decisions made Stick

Purpose: What SGSD decided, with the option chosen and why.

Contains: decision_recommendation + promotion_decision + operator_precedent CMBs; chosen path + rationale + rollback.

Must NOT contain: a menu with no recommendation.

Helps the operator: see where their authority was exercised on their behalf.

6 · Agent Autonomy Disclosure + Denominator panel Stick Minto

Purpose: What SGSD decided without the operator — and explicitly what it did NOT do.

Contains: the 5 denominator sub-arrays (scope_excluded / carve_outs_not_fired / alternatives_rejected / assumptions_made / gates_skipped).

Must NOT contain: an empty panel with no denominators_empty_reason.

Helps the operator: see the boundary of the work — the denominator, not just the numerator.

7 · Diagrams — file impact · gate waterfall · timeline · lineage Napkin

Purpose: Make the complex visible. Each diagram answers one question type.

Contains: 6 PUML renders, each with a mandatory takeaway <figcaption> + collapsed PUML source.

Must NOT contain: a diagram whose caption restates the title instead of the takeaway.

Helps the operator: grasp structure pre-cognitively, before reading.

8 · Risks & rollback SwD

Purpose: Genuine forward tension — what could still go wrong.

Contains: open risks, each with severity + rollback step + citation.

Must NOT contain: invented risks for drama; resolved risks (those go in "what changed").

Helps the operator: know what to watch before the next phase.

9 · What happens next Stick

Purpose: One recommended next action — beat decision paralysis.

Contains: the single primary action; alternatives collapsed in <details>.

Must NOT contain: an un-prioritised option menu.

Helps the operator: resume immediately without re-deciding.

10 · Fog Score + cross-milestone learning Stick SwD

Purpose: Cognitive-cost metric + roadmap-miner patterns — each metric paired with its telling instance.

Contains: Fog Score + top contributing signal in plain language; recurring drift classes.

Must NOT contain: a statistics barrage with no concrete instance.

Helps the operator: see whether SGSD is getting better or worse over time.

11 · Raw evidence appendix SwD (collapsed)

Purpose: Full accuracy underneath the accessible layer — the false-choice resolved.

Contains: full CMB ledger slice, full lineage DAG, all PUML source, manifest hashes.

Must NOT contain: anything not also referenced above; it is the substrate, not new content.

Helps the operator: audit to the byte when they need to — and ignore it when they don't.

Change vs current 17-section layout: the current chronicle has good raw material but a flat 17-section list. This collapses it to 11 ordered sections, 3 of which (7, 10, 11) hold most of the old detail in collapsed form. The reorder is pure Minto: decision → why → what → evidence → decisions → disclosure → visuals → risk → next → metrics → appendix.

Output 5 — Questions SGSD should answer every phase

A checklist the Chronicle Writer / Validator / Roadmap Miner should be able to answer for every phase. Grouped by concern; each group cites the book lens behind it.

Operator understanding Minto Stick

  • Can the operator get the verdict + next action without scrolling? (Minto answer-first)
  • Is the Big Idea expressible in one sentence?
  • Does the ELI5 use any internal term not defined inline? (Curse-of-Knowledge lint)
  • Would someone who skipped the whole autonomous run understand what changed?

Evidence trust Stick

  • Does every claim resolve to a CMB ID / file / test / commit the operator can open?
  • Are there any broken citations? (REPORT_BROKEN_CITATION)
  • Is each claim a testable credential — can the operator verify it themselves?
  • Where the chronicle asserts a takeaway-title conclusion, is that conclusion itself cited?

Cognitive load SwD

  • How many sections are open by default — and is that the minimum?
  • Is every low-signal section collapsed rather than deleted?
  • Does each panel put its reading key top-left, before the data?
  • What is the Fog Score, and does it auto-expand the must-read sections?

Risk & denominator Stick Minto

  • What did SGSD deliberately NOT do? (5 denominator sub-arrays)
  • Which hard carve-outs were available but did not fire?
  • What assumptions were made without operator confirmation?
  • Which open risks survive into the next phase, and what is each rollback?

Visual explanation Napkin

  • Does each diagram answer one of the six question types (who/what, how-much, where, when, how, why)?
  • Does every diagram have a takeaway caption — not a restated title?
  • Is the diagram tuned to an execution-oriented operator (Quantity + Execution + Comparison)?
  • Does the architecture diagram anchor on one central node?

Cross-book synthesis — where they agree, disagree, converge

Where the 4 books agree

  • Conclusion before support. Minto's top-down ordering, SwD's "lead with the ending" narrative flow, and Stick's "don't bury the lead / inverted pyramid" are the same rule in three vocabularies.
  • The expert is the problem. Stick's Curse of Knowledge, Minto's "readers impose their own grouping logic", and Napkin's "audience gets it before you stop explaining" all say: the author over-estimates the reader's context.
  • Structure is perceived before content. Minto ("the eye perceives logical structure first") and SwD (z-pattern, Gestalt) agree the layout itself is a message.

Where they diverge

  • Simplicity. Napkin explicitly warns against equating clarity with simplification — "make it visible, not simple." Stick's "Simple" element pushes the other way (find the core, compact it). Resolution for SGSD: simplify the wording (Stick), but do not simplify the diagrams below legibility (Napkin) — keep the lineage DAG complete.
  • Emotion. Stick wants emotional resonance; Minto is coldly logical. For an audit artefact consumed by one technical operator, Minto wins — emotion is not a chronicle goal.

Same principle, different language

"Answer first" = Minto top-down = SwD lead-with-the-ending = Stick inverted pyramid / Commander's Intent. "Testable credential" (Stick) = "the eye perceives structure / verify for yourself" instinct = SGSD's cited CMB ID. "Governing thought" (Minto) = "takeaway title" (SwD) = "Big Idea" (SwD) = "core message" (Stick Simple).

Bottom line

The single highest-value change is Rule 01 + Output 3: add an answer-first Operator Decision Panel and collapse the flat 17-section layout into the 11-section top-down order. That one reorder is endorsed by all 4 books under different names and directly serves DLB-11's cognitive-completeness axiom. Everything else (jargon lint, takeaway titles, evidence expanders, one-action-next) is incremental polish on top of it.
