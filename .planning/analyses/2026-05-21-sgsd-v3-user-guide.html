1. What is SGSD v3.0?

ELI5

SGSD is a system that helps you build software with AI agents without losing your mind. v3.0 makes the agents remember what they said, why they accepted things, and what's safe to do without asking you. You still get woken up for the important stuff — but only the important stuff.

v2.x SGSD orchestrated Codex through one big "send it to Codex" pipe. It worked but had three structural problems:

  1. Reviewers hallucinated and blocked good code. ATC v22-13c on Clarity ERP returned CRIT against file:line evidence that refuted the claim. SGSD's rule "if CRIT then fail" treated a false positive as a hard stop.
  2. Boards escalated to operator because context was lost. Each agent re-derived understanding from raw transcripts. Milestone WHY + persona priority + decision precedents didn't carry agent-to-agent.
  3. Memory died between sessions. No per-role "what I understood, why I accepted it, where it came from, whether it's original or echoed" persistence.

v3.0 SGSD-PRO adds a lineaged role-filtered cognitive memory layer underneath SGSD's existing central control plane. The shape is stolen from Mesh Memory Protocol and Pi2Pi, but the implementation is SGSD-native — no Pi-harness, no sym-mesh-channel, single-machine Windows-friendly.

Three substrates shipped

DLB-08 Mesh Memory Lite

Seven typed CMBs (Cognitive Memory Blocks), CAT7 envelope, lineage DAG, O(1) echo detection, Tier 0+1 evidence validator, pseudo-operator peer, hard-carve-out escalation gate.

DLB-09 Codex Pro Mode

10 typed Codex profiles, GREEN/AMBER/RED stoplight routing, native Codex review as first-class gate, PLAN-LOCKED.md formal contract, 5 fail-CLOSED Codex hooks.

DLB-10 Context Authority

Per-milestone YAML capsule (MILESTONE-CONTEXT, PERSONA-MATRIX, DOMAIN-ONTOLOGY, LEXICON, SOURCE-OF-TRUTH, NON-GOALS) projected into the mesh as context_anchor CMBs with staleness detection.

2. The mental model

SGSD             = air traffic control
Codex / Claude   = aircraft
Mesh Memory Lite = shared radar + black box + radio protocol
Pseudo operator  = trained duty officer
Real operator    = commander, only called when authority is exceeded
The architectural axiom

Mesh-shaped memory, central-shaped runtime. We're NOT building concurrent autonomous mesh convergence. We're building lineaged role-filtered memory under a central serialised orchestrator. Honest framing prevents claims we cannot back at N=1 machine.

The four binding invariants

  1. Observation / claim / decision are different classes. SGSD emits observations (execution_receipt). Agents emit claims (review_finding). Validators emit verdicts (evidence_verdict). Pseudo-operator emits decisions (decision_recommendation). Operators emit precedents (operator_precedent). SGSD must never treat a claim CMB as an observation CMB.
  2. CAT7 wraps; doesn't replace. CAT7 fields cite the YAML anchors; they don't invent new ontology terms. Canonical truth stays in YAML capsules.
  3. Hard carve-outs override LLM confidence. Production mutation / credentials / scope change / commercial impact / low confidence / destructive operations all force real_operator_required: true regardless of how confident the pseudo-operator's Tier 2 LLM judge is.
  4. Mesh-shaped memory, central-shaped runtime. Logical peers; sequential execution. No concurrent autonomous claims we can't back.

How information flows

Codex executes work → SGSD observes what happened → reviewer claims what might be wrong → evidence_validator checks whether the claim holds against current HEAD → pseudo-operator reads validated claims + context anchors + operator precedents → decides what SGSD should do → escalation_gate either lets SGSD continue OR routes to real operator. Every step writes a typed CMB to the mesh ledger so future agents can walk the lineage and not re-derive understanding.

4. The seven CMB types

A Cognitive Memory Block (CMB) is the atomic unit of v3.0 mesh memory. Every CMB has:

  • A unique key (sha256 of canonical payload, or semantic cmb-... identifier)
  • A type (one of the seven below)
  • A cat7 envelope: focus / issue / intent / motivation / commitment / perspective / mood
  • A type-specific body
  • A lineage (parents + ancestors of content-hash keys)
  • An authority_level declaring its cognitive class
observation

execution_receipt

Who emits: SGSD wrapper (never an agent)

Purpose: Record what actually changed and what checks actually ran. Observable facts only.

Body: commit_before/after, changed_files, tests_run, report_path/hash, acceptance_criteria_touched

claim

review_finding

Who emits: ATC / Codex native review / board reviewers

Purpose: A claim about risk, correctness, missing coverage, or policy breach.

Body: severity, claim, current_commit, optional file_path/line_*/quoted_excerpt

claim w/ authority

evidence_verdict

Who emits: evidence_validator

Purpose: Classify a review_finding as VERIFIED / REFUTED / STALE / UNVERIFIED / GUARDED CRIT.

Body: evidence_status, tier_used (0|1), decision_basis, optional refuting_evidence

decision

decision_recommendation

Who emits: pseudo_operator_peer

Purpose: What SGSD should do given evidence + context + policy.

Body: recommendation, authority_level (1-3), confidence (0-1), real_operator_required, context_pack_id, carve_outs_triggered

decision · highest

operator_precedent

Who emits: real operator

Purpose: Make operator decisions reusable. Highest authority unless superseded.

Body: precedent, decision context

projection

context_anchor

Who emits: context_authority (composer)

Purpose: Project YAML capsule content into the mesh. Canonical truth stays in YAML.

Body: canonical_source_path, canonical_source_hash, projection_summary

decision · terminal

promotion_decision

Who emits: SGSD

Purpose: Record state transition (PASS / PASS_WITH_REFUTED_REVIEW / FAIL_VERIFIED / NEEDS_OPERATOR / STALE_REVIEW).

Body: verdict, phase

The nuclear safety sign on the door: SGSD must never treat an agent claim CMB as an observation CMB. The schema enforces this via created_by + role + type constraints with SCHEMA-MML-02 errorMessages. Conflating claim and observation is how model-generated memory becomes fake truth.

5. Workflow — operator says "go" to phase close

What actually happens when you say /sgsd-orchestrate auto on a v3.0 phase:

1Operator: go. SGSD reads STATE.md + active phase CONTEXT.md.
↓
2SGSD dispatches Codex to author PLAN-LOCKED.md (v2-schema + lock metadata).
↓
3profile-resolver picks Codex profile based on phase type, risk, allowed_files.
↓
4stoplight classifies dispatch context as GREEN / AMBER / RED.
↓
5GREEN: Codex executor dispatched with hooks active. AMBER: goal lane or app-lab. RED: stop; route to escalation_gate.
↓
6Codex hook block-secret-leak runs on every prompt; block-forbidden-write + enforce-allowed-files run on every tool use; log-tool-event on every result; validate-stop-contract on stop.
↓
7SGSD wrapper observes diff + tests + report → emits execution_receipt CMB to mesh ledger.
↓
8native-review-runner reviews diff → emits one review_finding CMB per finding (lineage parent = receipt).
↓
9evidence_validator (Tier 0 deterministic + Tier 1 heuristic) emits evidence_verdict CMB per finding.
↓
10echo-detector intersects incoming claim's ancestors with SGSD's own produced keys. Repeat-claims flagged.
↓
11pseudo_operator_peer reads evidence_verdicts + context_anchors + operator_precedents → emits decision_recommendation.
↓
12escalation_gate checks 6 hard carve-outs. If ANY fire → real_operator_required: true regardless of confidence.
↓
13SGSD emits promotion_decision (PASS / PASS_WITH_REFUTED_REVIEW / NEEDS_OPERATOR) → phase close OR escalation packet.
Why this is better than v2.x

In v2.x: Codex returned a prose report → SGSD ATC parsed it loosely → if "CRIT" appeared, hard stop. False positives froze the loop. In v3.0: every claim becomes a typed CMB with lineage. Every claim is evidence-validated. Stale echoes are detected. Hard carve-outs prevent autonomous production writes. Operator escalation requires context-pack + pseudo-op recommendation first.

Stoplight routing

Before any Codex run gets write permission, SGSD classifies it:

● GREEN

Bounded executor runs.

  • locked_plan: true
  • allowed_files ≤ 12
  • acceptance_command exists
  • risk: low | medium
  • no production writes
  • no secrets required

● AMBER

Goal lane or app-lab.

  • long validation loop
  • broad bounded roots
  • temp worktree required
  • human/board review before apply

● RED

No execution. Route to board/operator.

  • no locked_plan
  • no acceptance command
  • high ambiguity
  • production / SAP / Mongo / Qdrant mutation
  • secrets required
  • destructive command required

7. Hard carve-outs (the restraint case)

The escalation_gate enforces 6 hard rules. If any rule fires, real operator is required regardless of pseudo-operator confidence.

🏭
production_mutationAny write to SAP, Mongo, Qdrant, Elasticsearch, customer DB, or `prod*` files
🔑
credential_or_securityAny reference to *.env, secrets/, credentials/, tokens, keys, certs, or auth/security changes
🎯
milestone_scope_changeIntroducing or removing a milestone-level commitment
💼
commercial_legal_policyPricing, contracts, public statements, customer-visible commitments
⚠️
low_confidencePseudo-operator confidence < 0.70
💥
destructive_or_irreversiblegit history rewrite, force-push, DROP TABLE, anything not easily undoable
Fixture D — proved by SAC-P109-05: A test case where pseudo-operator has VERIFIED_CRIT evidence + LLM-judge confidence 0.95 + target_systems=[sap] returns real_operator_required: true with carve_outs_triggered: ['production_mutation']. The duty officer knows when to pick up the red phone. Autonomous loop cannot bypass real operator authority on production mutation regardless of how confident the LLM judge is.

8. Context Authority capsule

Every v3.0+ milestone gets 6 hand-authored YAML files under .planning/milestones/{milestone}/context/:

MILESTONE-CONTEXT.yaml

Milestone WHY, primary user outcome, personas (with priority), source-of-truth mappings, non-goals, operator preferences.

PERSONA-MATRIX.yaml

Per-persona cares_about / usually_ignores / search_bias.include / search_bias.suppress.

DOMAIN-ONTOLOGY.yaml

Entity types, their children, source-of-truth mappings per aspect, invariants, behavioral actions.

LEXICON.yaml

Polysemy + domain-specific terminology. Terms with senses + which personas typically mean which sense.

SOURCE-OF-TRUTH.yaml

Per data-class: authoritative system + canonical path (file or DB). Where to look when there's a conflict.

NON-GOALS.yaml

Explicit out-of-scope items with rationale + which scope (this milestone / this project / permanently).

The context-composer.cjs --milestone vX.Y projects all 6 into the mesh ledger as context_anchor CMBs with canonical_source_path + canonical_source_hash. If the source file's sha256 changes, the anchor is "stale" and must be re-projected before use.

Why YAML is canonical, not the mesh CMB

YAML files live in git and can be hand-edited / reviewed / diff'd by humans. Mesh CMBs are projections — fast for agents to consume but not authoritative. If the two diverge, YAML wins and the anchor gets re-projected. This prevents the mesh layer from becoming a second source of truth that nobody can audit.

9. Usability guide

Starting a new milestone

1. Create .planning/milestones/{milestone}/INTENT.md (mission + outcome)
2. Create .planning/milestones/{milestone}/ROADMAP.md (phases + exit criteria)
3. Create .planning/milestones/{milestone}/REQUIREMENTS.md (REQ-* coverage matrix)
4. Author the 6 Context Authority YAML files:
     cp super-gsd/templates/MILESTONE-CONTEXT.template.yaml \
        .planning/milestones/{milestone}/context/MILESTONE-CONTEXT.yaml
     # (repeat for the other 5 templates)
     # edit each to match this milestone
5. Run context-composer to publish anchors:
     node super-gsd/tools/context-authority/context-composer.cjs \
       --milestone {milestone}
6. Update .planning/STATE.md frontmatter (milestone, milestone_status, status)
7. Start phase work: /sgsd-orchestrate auto

Authoring a phase

1. Create .planning/milestones/{m}/phases/{NN-slug}/{NN}-CONTEXT.md
   - Lock binding invariants
   - List files this phase will create
   - Specify semantic acceptance criteria (real-data; SCHEMA-09 enforced)
2. SGSD auto-dispatches Codex to author PLAN-LOCKED.md
3. SGSD auto-dispatches Codex executor under stoplight + hooks
4. Run the phase's run-self-test.cjs to verify
5. Author {NN}-VERIFICATION.md
6. Update STATE.md progress block

10. Examples

Example 1 — A false CRIT from ATC gets refuted automatically
  1. Codex executor implements a schema change in app/services/models.py.
  2. SGSD wrapper emits execution_receipt: commit_after=54000ffd, changed_files=[models.py], tests_run=[18 python pass, 22 frontend pass].
  3. ATC reviewer reads diff, emits review_finding: severity=CRIT, claim="event model omits method/confidence fields", file_path=models.py, line_start=73, line_end=76, quoted_excerpt="...".
  4. evidence_validator Tier 0 deterministic check: models.py:73-76 is read from disk at HEAD; quoted_excerpt is compared. Match? No — the file DOES contain the fields the claim says are missing.
  5. evidence_validator emits evidence_verdict: evidence_status=REFUTED_CRIT, decision_basis="claim contradicted by file at lines 73-76 at HEAD", refuting_evidence=[models.py:73-76].
  6. pseudo_operator_peer reads the refuted verdict, builds decision context. No carve-outs fire (no production_mutation, no credentials, confidence high).
  7. pseudo_operator_peer emits decision_recommendation: recommendation="PASS_WITH_REFUTED_REVIEW", authority_level=3, confidence=0.93, real_operator_required=false.
  8. SGSD emits promotion_decision: verdict=PASS_WITH_REFUTED_REVIEW, phase=N.
  9. Operator is NOT woken. The false CRIT was structurally caught. Audit trail in mesh ledger preserves all 5 CMBs for future review.
Example 2 — Production mutation forces escalation (Fixture D)
  1. A phase's PLAN-LOCKED.md declares target_systems: [sap] + destructive: true.
  2. stoplight classifies → RED (production_writes triggers RED criteria).
  3. SGSD does NOT dispatch Codex. Instead routes to escalation_gate.
  4. escalation_gate.checkCarveOuts(context) returns: carve_outs_triggered=['production_mutation'], allow_autonomous=false, real_operator_required=true.
  5. Even if pseudo_operator_peer's Tier 2 LLM judge had confidence 0.99, the production_mutation carve-out is HARD — it overrides confidence.
  6. SGSD writes an escalation packet (decision_recommendation with real_operator_required: true + cited carve-outs + missing-context list + structured choice options) and stops the loop with a clear status to the operator.
  7. Operator IS woken with full context. This is the right outcome — production writes need human authority.
Example 3 — Echo detection catches a recycled claim
  1. Phase N: ATC emits review_finding A with claim "missing provenance fields". evidence_validator marks REFUTED_CRIT (file has the fields).
  2. Phase N+1: Same code area, ATC RE-EMITS review_finding A' with same claim. evidence_validator runs.
  3. echo_detector computes ancestors(A') and intersects with SGSD's own produced keys. The previously-emitted evidence_verdict for A is found in the intersection.
  4. echo_detected: true is flagged on the new CMB's body.
  5. pseudo_operator_peer sees the echo flag + the prior refutation → recommends PASS_WITH_REFUTED_REVIEW without burning new evidence-validation cycles.
  6. The "ATC keeps re-emitting the same false positive" failure mode (Clarity v22-13c root cause class) is structurally prevented from looping.
Example 4 — Context Authority resolves a persona conflict
  1. Decision: "Should the product search index include BOM child items alongside parent products?"
  2. Without v3.0: board would deliberate, lack persona priority, escalate to operator.
  3. With v3.0: pseudo_operator_peer reads PERSONA-MATRIX.yaml context_anchor → sees sales is primary, procurement is secondary.
  4. Cross-references SOURCE-OF-TRUTH.yaml → confirms product structure lives in BOM DB; web visibility owned by web catalogue.
  5. Cross-references LEXICON.yaml → "product" has senses sellable_product (sales) and bom_component (procurement); the question is about default search behavior.
  6. pseudo_operator_peer emits decision_recommendation: "Index BOM children but suppress in default sales-facing result set; expose via procurement filter." Cites context anchors as evidence. confidence=0.87, real_operator_required=false.
  7. SGSD continues. Operator not woken. Audit trail in mesh ledger.

12. FAQ

Why no Pi-agent-harness?

Anthropic's OAuth Terms of Service forbid non-Anthropic harnesses calling Claude via OAuth. Operator constraint; not a technical limitation.

Why no sym-mesh-channel?

The MMP paper's sym-mesh-channel plugin is a great reference implementation but its Anthropic Plugin Directory propagation was still unresolved as of 2026-04-21 (github.com/anthropics/claude-plugins-official/issues/1512). Optional experiment branch only; not in v3.0 critical path.

Why not concurrent autonomous mesh like the MMP paper?

Single-machine Windows 11 box. The MMP paper's N=3 mesh runs on Mac+Windows with Bonjour mDNS. We get the SEMANTIC properties (per-field admission, lineage, remix) but not the concurrent-autonomous properties. Honest framing: mesh-shaped memory, central-shaped runtime.

Why don't executors emit CMBs?

Agents emit claims. SGSD emits observations. Conflating the two is how model-generated memory becomes fake truth. SGSD's execution_receipt.cjs wraps the executor and emits an observation CMB from observable facts (git diff, test results, report hash). The executor itself never authors a CMB in MVP.

How does pseudo_operator_peer decide when to escalate?

It calls escalation_gate.checkCarveOuts(context). If ANY of the 6 hard rules fire (production_mutation, credential_or_security, milestone_scope_change, commercial_legal_policy, low_confidence, destructive_or_irreversible), real_operator_required=true is forced regardless of LLM-judge confidence.

What's the difference between SCHEMA-09 and SCHEMA-MML-02?

SCHEMA-09 is from v2.9 / DLB-07 / plan-schema-v2: rejects PLAN.md files without semantic_acceptance_criteria. SCHEMA-MML-02 is from v3.0 / DLB-08 / cmb.schema.json: rejects CMBs where the created_by role doesn't match the CMB type (e.g. an agent trying to author an execution_receipt).

Where do operator_precedent CMBs come from?

Currently, manually — when the operator makes a decision touching SGSD state, you can append an operator_precedent CMB to the ledger as a reusable precedent. Future v3.1 work could auto-emit these from AskUserQuestion responses, but that's not in v3.0.

How do I add a new Codex hook?

(1) Write the hook script under super-gsd/tools/codex-hooks/<name>.cjs with stdin JSON parsing + exit 0/non-0 contract. (2) Add it to .codex/hooks.json under the appropriate event. (3) Extend super-gsd/tools/codex-hooks/run-self-test.cjs to cover the new hook. Run the self-test to verify.

What if the mesh memory ledger gets too big?

The ledger is append-only JSONL. At 10K-100K CMBs it's still tractable for grep + lineage walks. Beyond that, future v3.1 work could partition by milestone, compact superseded CMBs, or index via Qdrant (deferred per NG-05). Until then: don't worry about it.

Can I use v3.0 without DLB-10 (Context Authority)?

Yes. DLB-08 (Mesh Memory Lite) + DLB-09 (Codex Pro Mode) work standalone. DLB-10 capsule is OPT-IN: if a milestone has the 6 YAML files, pseudo_operator_peer reads context anchors; if not, it falls back to milestone INTENT/REQUIREMENTS only.
