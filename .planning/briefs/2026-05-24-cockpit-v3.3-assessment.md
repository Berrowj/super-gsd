# Cockpit v3.3 — Live Contextual Awareness

> Translate the v3.1 chronicle's answer-first explanation grammar into a live cockpit
> experience. Operator gets full contextual awareness during the run: what this phase is,
> why we're building it, what it unlocks, what was needed before unlock, and what to do next.
> Grounded in the design + explanation corpus (Minto, Heath, Roam, Munroe, Duarte, Sullivan,
> Knaflic) and operator's own validated 6-stage pipeline pattern.

## Situation

v3.2 (DLB-12) shipped a tight 405-line answer-first cockpit-sidecar (`super-gsd/tools/cockpit-sidecar/cockpit-sidecar.cjs`) with NORTH STAR + DO NEXT + ⚠ ONE ALERT + SUPPORTING block, 18/18 self-test, binding_fail=0 cross-surface conformance. That artifact is solid as the *answer-first compact* surface.

The surface the operator actually watches all day is different: `super-gsd/scripts/sgsd-codex-monitor.ps1` — a 2,446-line PowerShell live monitor rendering ~15 panels (ClaudeEli5Panel, ClaudeNowPanel, CodexHistory, VerifyGates, GateSavings, AtcReviewSteps, GateSynopsis, GateFocus, PhaseGoalBrief, PhaseEvidenceSummary, VtpUsageForEli5, multiple gate-compact rows, plus 8 supporting render functions). It includes a Haiku-narrated ELI5 panel + PhaseContextForEli5 helper. **This is "the cockpit"** in operator language.

Two operator complaints (2026-05-24):

1. **Freshness** — doesn't always show the most up-to-date relevant information.
2. **Usefulness** — a lot of the info isn't useful.

Two operator preferences:

- The Context and ELI5 sections are useful and should be **expanded**, not stripped.
- The full v3.1 chronicle-HTML explanation experience should be translated into live cockpit terms — operator wants contextual awareness during the run, not only at phase close.

## Stakes

v3.2 closed the answer-first primitive but only on the *compact terminal sidecar*. The daily-watched surface (PowerShell live monitor) is pre-v3.2 — it does not honour R01 (lead with the decision), R04 (one recommended action), R11 (no un-glossed jargon) at the binding-gate level. Without v3.3 the cockpit redesign work stays half-done: tight summary in one window, sprawling pre-v3.2 panel-soup in another.

Cost of getting this wrong:
- Operator continues running unattended autonomous loops with degraded situational awareness, retains the v3.2-era habit of checking STATE.md frontmatter manually instead of trusting the cockpit.
- ELI5 narration (the part the operator likes) stays disconnected from the rationale chain (CONTEXT.md → INTENT.md → unlock graph → SUMMARY.md cascade). Currently no single panel answers *why* this phase, *what it unlocks*, or *what was needed before*.
- ORDER-PIPELINE-SPEC.pdf (operator's own work) names a 6-stage pipeline pattern that's been independently validated at JCL — letting that pattern stay outside SGSD wastes a high-confidence design asset.

Cost of getting this right:
- One surface answers operator's "where are we / why does this matter / what's blocked / what's next" without scanning. Halves the time-to-decision during unattended runs.
- Chronicle layer (v3.1) + answer-first cockpit (v3.2) + live narrative (v3.3) become one continuous explanation grammar — same vocabulary, same hierarchy, same conformance rules. The conformance gate (advisory→binding promotion already in v3.2 backlog) covers all three surfaces.

- **Architecture lock 13** (from v3.2 D6): all cockpit changes live under `super-gsd/tools/cockpit-sidecar/` and `super-gsd/scripts/sgsd-codex-monitor.ps1`. Zero touches to `cockpit-state/*`, `tests/cockpit-acceptance/*`, `tests/cockpit-regression/*`.
- **JSON contract frozen** — `--json` output of `cockpit-sidecar.cjs` is byte-stable. v3.3 may *add* keys but may not break existing ones.
- **Invariant 5** — cockpit reads ledger state read-only; deterministic functions only, no agent opinion in the data layer. (Agent ELI5 narration is its own panel, clearly marked.)

## The Design System — 11 principles, with citations

| # | Principle | Source | Cockpit decision |
|---|---|---|---|
| **P1** | **Sharp-edged 100% stages** | Brooks, *Mythical Man-Month* `[VTP-SUBSTRATE]` | Every stage in the per-phase pipeline is binary: ✓ done / ⏳ active / ⏸ pending / 🛑 blocked. No percent fields. Wires to `semantic_acceptance_criteria` (P97.5 / DLB-07 schema). |
| **P2** | **Cause + ETA on every >1s operation** | Norman, *Design of Everyday Things* `[VTP-SUBSTRATE]` | Codex dispatch panel shows cause + predicted finish, not just elapsed time. ETA is derived from rolling P50 of last 5 same-stage runs. |
| **P3** | **6-stage pipeline with SLA + named owner + blocker flag** | `wiki/meetings/project-clarity-extraction.md` `[VTP-SUBSTRATE]` + ORDER-PIPELINE-SPEC.pdf `[OPERATOR-SPEC — UNREAD]` | The phase progresses through 6 named stages (`discuss → research → vtp-enrich → plan → execute → verify`). Each has owner (Codex / Claude / operator), SLA window, current time-in-stage, blocker flag. Identical pattern to operator's JCL order pipeline. |
| **P4** | **Data-ink ratio — every pixel justifies itself** | Tufte canonized paper `[VTP-SUBSTRATE]` | Migration audit weapon for the 15+ panels in `sgsd-codex-monitor.ps1`: presumed-guilty-of-noise until proven useful. |
| **P5** | **Sparklines for trend at zero space cost** | Tufte (sparklines) `[VTP-SUBSTRATE]` | 12-px inline sparkline next to `fog_score`, `dispatch_count`, `token_spend` showing 24h trend. Reveals direction without a separate panel. |
| **P6** | **Macro + micro both legible** | Tufte test `[VTP-SUBSTRATE]` | Self-test: step-back screenshot test (overall pattern reads) + lean-in screenshot test (each value reads). Both must pass before lock. |
| **P7** | **Visual hierarchy — one loud line** | Krug, *Don't Make Me Think* `[VTP-SUBSTRATE]` | Already shipped in v3.2 R04. Extended in v3.3 to per-section scope: each band has exactly one loud element. |
| **P8** | **3-layer cognition: visceral → behavioral → reflective** | Norman three-level analysis `[VTP-SUBSTRATE]` | Maps to the 3-band IA below. Currently `sgsd-codex-monitor.ps1` interleaves all three; v3.3 separates them spatially. |
| **P9** | **Main success scenario + named extensions** | Cockburn, *Writing Effective Use Cases* `[VTP-SUBSTRATE]` | Frame each phase as a goal-pursuit story: happy path is the 6-stage pipeline; extensions are named events (`SAC_DRIFT`, `CODEX_FILE_BLOCK`, `BOARD_INTERRUPT`, `OPERATOR_PAUSE`). When an extension fires, the cockpit shows which one + recovery path. |
| **P10** | **Minto SCQA + governing thought + MECE** | Minto, *Pyramid Principle* `[CANONICAL]` | Each major section opens with SCQA: Situation → Complication → (implicit Question) → Answer (governing thought = section heading). Supporting elements are MECE — no overlap, exhaustive coverage. |
| **P11** | **SUCCES test on every WHY panel** | Heath, *Made to Stick* `[CANONICAL]` | WHY/CONTEXT panel must pass: **S**imple (one core idea), **U**nexpected (surface the surprise — what does this small phase unlock), **C**oncrete (file names + line numbers, not abstractions), **C**redible (cited from CONTEXT.md / INTENT.md / SUMMARY.md), **St**ories (frame as arc, not status). Drop E (emotional — wrong audience). |
| **P12** | **6×6 visual frame mapping** | Roam, *Back of the Napkin* `[CANONICAL]` | Each data type uses its native visual frame: who/what → portrait; how much → chart; when → timeline; where → map; how → flowchart; why → multi-variable. Stop using text-block for all 6. |
| **P13** | **Common-words constraint on ELI5** | Munroe, *Thing Explainer* `[CANONICAL]` | The ELI5 panel is lint-checked against a controllable common-words list. Out-of-list terms must be glossed inline. Mechanically testable. Honours v3.2 R11 at the lint level. |
| **P14** | **What is / what could be — oscillating arc beat** | Duarte, *Resonate* `[CANONICAL]` | The arc panel narrates: *what is now* (current phase + predecessors complete) → *what could be* (named downstream unlocks) → S.T.A.R. moment (the binding unlock) → call to action (DO NEXT). |
| **P15** | **Audience-first ≤10 words per top-line** | Sullivan, *Simply Said* `[CANONICAL]` | The operator's "audience" = the current decision (continue / pause / intervene). Every panel begins with the answer for that decision. Top-line statements ≤ 10 words (already in v3.2 `--brief`). |
| **P16** | **Declutter-then-highlight binary audit** | Knaflic, *Storytelling with Data: Let's Practice!* `[CANONICAL]` | Migration audit for each PowerShell panel is binary: declutter (strip to essentials, keep) or kill (off-stage). The "highlight one thing" rule = v3.2 R04 extended. |
| **P17** | **5-tier functional colour palette** | GitHub Primer `[VTP-SUBSTRATE]` | accent / success / attention / severe / danger / done — for the alert grammar already in `alert-grammar.cjs`. No more than 5 colours total across the surface. |

## Information Architecture — three bands

```
┌─ BAND 1 · GOVERNING THOUGHT (visceral · always loud) ────────────────┐
│  NORTH STAR  ▸ DO NEXT  ⚠ ONE ALERT (+N more)                         │
│                                                                       │
│  Honors: Minto answer-first · Sullivan ≤10 words · Krug one-loud-line │
│  Sourced from: v3.2 D2 cascade (unchanged) + alert-grammar.cjs        │
└───────────────────────────────────────────────────────────────────────┘
┌─ BAND 2 · MECE SUPPORTING POINTS (behavioral · scannable) ───────────┐
│  STAGE PIPELINE   discuss ✓  research ✓  vtp ✓  plan ⏳  exec  verify  │
│                   (each stage: owner · time-in-stage · SLA · blocker) │
│  WHY-RUNNING      cause: SAC drift · ETA: ~3min · owner: codex-plan   │
│  UNLOCKS          P131 (live narrative cockpit) · P132 (live ELI5)    │
│  BLOCKED-BY       nothing                                              │
│                                                                       │
│  Honors: Project-Clarity-Suite stages · Norman cause+ETA · Brooks     │
│          sharp-edged · Cockburn main-success-scenario · Minto MECE    │
└───────────────────────────────────────────────────────────────────────┘
┌─ BAND 3 · RATIONALE / STORY (reflective · on demand / scroll) ───────┐
│  CONTEXT       one paragraph from CONTEXT.md cascade (Heath Concrete) │
│  ELI5          Haiku narration, lint-checked words (Munroe constraint)│
│  WHAT IS       what we have now (Duarte beat 1)                       │
│  WHAT COULD BE what this unlocks (Duarte beat 2)                      │
│  WHY THIS PHASE causal anchor: PROJECT.md core-value + INTENT.md      │
│  EVIDENCE TRAIL one-line citations: SAC sources, plan §, gate result  │
│                                                                       │
│  Honors: SUCCES test · Duarte arc · Heath story · operator-validated  │
└───────────────────────────────────────────────────────────────────────┘
```

### Roam 6×6 data-shape mapping

| Data type | Visual frame | Where it lives |
|---|---|---|
| **who / what** (active phase, owner, agent) | portrait | Band 1 supporting + Band 2 stage owner cells |
| **how much** (fog, dispatches, tokens) | inline sparkline (12-px) | Band 2 supporting line |
| **when** (stage progress, ETA) | timeline / pipeline strip | Band 2 STAGE PIPELINE |
| **where** (phase ↔ neighbour graph) | dependency map | Band 3 UNLOCKS + Band 3 WHY anchor (small graph render) |
| **how** (gate chain, recovery flow) | flowchart | Band 2 WHY-RUNNING (when extension fired) |
| **why** (rationale, intent) | multi-variable text block | Band 3 WHY THIS PHASE |

## Keep / Kill audit framework (sgsd-codex-monitor.ps1)

Each existing panel is scored against this matrix before migration:

| Question | If YES | If NO |
|---|---|---|
| Does this panel earn its pixels under the data-ink rule (P4)? | Keep | **Kill** |
| Does it answer a question the operator actually asks during a run? | Keep | Off-stage (drill-in only) |
| Is it one of: governing thought / supporting MECE / rationale? | Map to its band | **Kill — uncategorizable** |
| Does it duplicate information shown in another panel? | Merge | Kill the duplicate |
| Would a senior operator mass-delete it after one week? | Kill | Keep |
| Does the current panel cite its source (file / line / rule)? | Keep | **Add provenance line** before keeping |

### Why P132 was inserted

Original brief had 6 phases ending in monitor migration. After 2026-05-24 architecture discussion, the localhost-live HTML cockpit became the obvious primary surface: it shares grammar with the chronicle HTML + sidecar `--html` (one design system, one conformance gate), avoids the cost of every panel addition needing 100 lines of PowerShell string-formatting, and the v3.2 `--html` mode already does 60% of the work. PowerShell monitor stays as terminal fallback during transition; P133 scope shrinks correspondingly. Lag is not a concern at SGSD's grain (1-2s SSE freshness is well below stage-transition rate).
