# Phase 119 — Milestone Chronicle + Roadmap Miner

> The v3.1 capstone. Cross-phase roll-up + cross-milestone retrospective analysis. Ships `milestone-chronicle.cjs` (rolls up all phases of a closed milestone into one chronicle) + `mine-roadmap.cjs` (process-mining over closed milestones to surface recurring patterns / waste / drift). Optionally produces the one-off v3.0 milestone retrospective (the DLB-11 forward-only exception).

## Goal

Ship `milestone-chronicle.cjs` + `mine-roadmap.cjs` + self-test extension + golden milestone-chronicle fixture + (optionally) the v3.0 milestone retrospective chronicle. After this phase, an operator can:

1. Run `milestone-chronicle.cjs --milestone v3.1` → get a single HTML chronicle for the whole milestone
2. Run `mine-roadmap.cjs` → get a cross-milestone retrospective JSON identifying gate hot spots, common drift causes, plan-revision rates

## Binding invariants

1. **Milestone chronicle is a PROJECTION across phase chronicles.** Reads `.planning/chronicles/{milestone}/P*/chronicle-context.json` for each closed phase; rolls up into a single milestone chronicle context that validates against the same chronicle.schema.json (with `chronicle_type: "milestone"`).
2. **Roadmap miner is read-only across closed milestones.** Walks `.planning/milestones/*/SUMMARY.md` + chronicle INDEX rows + token-attribution log + chronicle-validation log. Computes per-gate frequency + verdict distribution + dispatch count + token spend per phase.
3. **Forward-only policy preserved.** v3.0 retrospective is OPTIONAL one-off. Skipping is the default; opting in must be explicit via `--include-v3.0-retro` flag.
4. **All outputs flow through P116 validator + P117 publisher.** Milestone chronicle goes through the same pipeline as phase chronicles. No bypass.
5. **Miner output is JSON only.** No HTML synthesis for the miner — it produces structured data the operator inspects with `jq` or that future tools consume. Keeps scope tight.

## milestone-chronicle.cjs contract

### Invocation
```
node super-gsd/tools/chronicle/milestone-chronicle.cjs \
  --milestone <id> \
  --out <path-to-milestone-chronicle-context.json> \
  [--planning-root .planning] \
  [--phase-glob "P*"]
```

### Pipeline
1. List all phase directories under `.planning/milestones/{milestone}/phases/` matching `--phase-glob`
2. For each phase, find its chronicle context (either at `.planning/chronicles/{milestone}/P{N}/chronicle-context.json` if published, OR build on-the-fly from phase artefacts using `build-context-pack.cjs` if not yet published)
3. Roll up sections across phases:
   - `observations` = concat of all phase observations
   - `claims` = concat
   - `decisions` = concat
   - `denominators` = merged sub-arrays (deduped); `denominators_empty_reason` only if ALL phases have empty
4. Emit milestone chronicle context with `chronicle_type: "milestone"`, `id: "chronicle-{milestone}-milestone"`, source.milestone_id set, source.phase_id null (or "milestone")
5. Validate against chronicle.schema.json before writing
6. Write atomically

### Exit codes
- 0 — success
- 1 — milestone has no closed phases (or phase-glob matches none)
- 2 — schema validation failed
- 3 — write failed
- 4 — usage error

## mine-roadmap.cjs contract

### Invocation
```
node super-gsd/tools/chronicle/mine-roadmap.cjs \
  [--planning-root .planning] \
  [--chronicle-index .planning/chronicles/INDEX.jsonl] \
  [--validator-log .planning/metrics/chronicle-validation-log.jsonl] \
  [--executor-log .planning/metrics/codex-executor-log.jsonl] \
  [--token-attribution .planning/metrics/token-attribution.jsonl] \
  --out <path-to-roadmap-mine-output.json>
```

### Pipeline
1. List all milestones under `.planning/milestones/` with `SUMMARY.md`
2. For each milestone:
   - Count phases per status (PASS / PASS-WITH-DEFERRED / BLOCKED)
   - Count chronicle publications + verdict distribution (GROUNDED / UNGROUNDED / BROKEN / CONTAMINATED)
   - Sum dispatch counts + token spend per phase (from executor-log + token-attribution)
   - Identify drift patterns: phases requiring N>=2 patch rounds before close (from .planning/metrics/* signals)
3. Emit JSON:
   ```json
   {
     "schema_version": "1.0",
     "generated_at": "<iso>",
     "milestones": [
       {
         "id": "v3.1",
         "phases_total": 7,
         "phases_passed": 7,
         "chronicle_verdicts": {"REPORT_GROUNDED": 7, "REPORT_UNGROUNDED": 0},
         "dispatch_count_total": 42,
         "token_spend_total": 1234567,
         "patch_round_distribution": {"0": 4, "1": 1, "2": 2},
         "fog_score_avg": 28,
         "recurring_drift_classes": ["schema-shape-divergence-in-codex-benchmarks"]
       }
     ],
     "cross_milestone_patterns": [
       {
         "pattern": "Codex executor authors fixtures with stale schema_version/kind shape",
         "occurrences": 3,
         "milestones": ["v3.1"],
         "mitigation": "Inline schema-shape reference in executor prompt"
       }
     ]
   }
   ```

### Exit codes
- 0 — success
- 1 — no closed milestones found
- 2 — write failed
- 3 — usage error

## Optional: v3.0 retrospective chronicle

DLB-11 forward-only policy: v3.0 phases (P106-P112) closed without chronicles. P119 may author ONE milestone-level retrospective chronicle for v3.0 as the documented exception. Steps:

1. Run `milestone-chronicle.cjs --milestone v3.0 --out .tmp-sgsd/v3.0-retro-context.json`
2. Run `render-html.cjs --context ... --out .tmp-sgsd/v3.0-retro.html`
3. Run `validate-chronicle.cjs --chronicle ... --context ...`
4. Run `publish.cjs --bundle ...` to `.planning/chronicles/v3.0/MILESTONE/`

This is dogfooding the chronicle pipeline. If it works end-to-end on real v3.0 data, the v3.1 substrate is validated against real-world load.

Default at P119: the retrospective generation is OPT-IN via `--include-v3.0-retro` (kept lightweight; can be run post-phase-close as a verification step). Self-test exercises the build/render/validate path against synthetic input; the v3.0 actual retro is operator's choice.
