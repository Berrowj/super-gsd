# Plan 97.5-01 — Schema Enforcement of Semantic Acceptance Criteria

## Goal

Make `validate.cjs` mechanically reject any v2 plan whose `semantic_acceptance_criteria` array is absent, empty, or contains entries missing `input` / `expected_outcome` / `verification_cmd`.

The schema change is the load-bearing layer of DLB-07's protection plan. Without it, the rule lives only in markdown and depends on agent diligence to be applied.

## Bootstrapping note

The schema change is backward-breaking by design. Every existing v2 plan without `semantic_acceptance_criteria` will fail validation after t1 lands. t3 audits the scope of that breakage and produces `97.5-BACKFILL.md` so the operator can decide per-phase whether to backfill the field or grant a `skip_gates` exemption.

This plan file itself includes `semantic_acceptance_criteria` (see frontmatter) so it self-validates against the new schema once t1 ships.

## Dispatch

Codex executor via `super-gsd/scripts/codex-executor.sh`. Serial SDD: t1 → t2 → t3. Bounded read-pack per task; do not share Codex context across tasks.

## Why no VTP enrichment

This is project-specific tooling work (our own plan-schema validator). No external book/paper precedent is load-bearing for the implementation. VTP would add noise, not signal. The orchestrator may bypass VTP for this plan and write the reason to the metrics log.
