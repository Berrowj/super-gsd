## Recommended next action

Two viable paths, decided by the operator per phase:

### Path A — Backfill before the phase dispatches

For each upcoming v2.9 phase author, run `/sgsd-write-plan` (which validates against the v2 schema) instead of hand-authoring the legacy frontmatter. The validate hook will refuse to write a plan that lacks SAC. Cost: per-phase author time; benefit: every future plan has a real-data semantic AC.

### Path B — `skip_gates` exemption

Phases whose code is already complete and whose plans pre-date P97.5 may add `skip_gates: ["plan-schema-v2"]` to the plan frontmatter for a one-time historic exemption. Operator must sign off per phase. This is a debt declaration, not a fix — the plan still doesn't have a semantic AC, just a get-out-of-jail card.

### Not recommended — bulk migration

Migrating all 18 plans in one go would conflate "schema migration" with "semantic AC content authoring". The two should be separated: the author of each phase knows what a meaningful semantic AC looks like for that phase's deliverable. A bulk pass would produce placeholder SACs that defeat DLB-07.

## Out of scope

This audit does not modify any existing plan. P97.5's contract is "make the gap visible". Backfill is the owning phase author's job.
