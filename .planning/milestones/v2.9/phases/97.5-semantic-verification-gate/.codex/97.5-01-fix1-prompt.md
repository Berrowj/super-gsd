## What you are fixing

`super-gsd/templates/plan-schema-v2.json` currently emits the wrong error code (SCHEMA-01) for an empty `semantic_acceptance_criteria: []` array. Root cause: the `minItems` errorMessage is at plan level, but the `minItems: 1` constraint is at property level. ajv-errors only intercepts errorMessages at the same schema level as the constraint.

## The single change

Inside `super-gsd/templates/plan-schema-v2.json`:

1. **Remove** the `"minItems": "plan 'semantic_acceptance_criteria' must contain >=1 entry (SCHEMA-09)"` line from the plan-level `errorMessage` block (lines around the top-level `errorMessage`).

2. **Add** an `errorMessage` block inside the `properties.semantic_acceptance_criteria` object so it sits next to `"minItems": 1`. The new state should look exactly like this:

   ```json
       "semantic_acceptance_criteria": {
         "type": "array",
         "minItems": 1,
         "items": { "$ref": "#/definitions/semantic_ac" },
         "errorMessage": {
           "minItems": "plan 'semantic_acceptance_criteria' must contain >=1 entry (SCHEMA-09)"
         },
         "description": "Each entry: a falsifiable claim that a real-world input produces a specific outcome (DLB-07, SCHEMA-09)."
       },
   ```

Do not touch any other field. The plan-level `errorMessage.required.semantic_acceptance_criteria` (the SCHEMA-09 missing-field message) must remain in place — only the `minItems` line moves.
