# v1.6 Proposed Phase Plan

This is a phase seed for Claude/SGSD. It is not active until promoted.

## Enrichment Summary

v1.6 is now Cockpit 2.0 plus startup verification.

The previous boot/setup work is not thrown away. It becomes evidence to verify.
The new build target is the operator model: what SGSD is doing, why it matters,
what it unlocks, what is blocked, which agents worked, what Codex is doing, and
what should happen next.

Book lens:

- The Design of Everyday Things: cockpit is the system image.
- Don't Make Me Think: answer the user's questions before showing internals.
- Writing Effective Use Cases: visible lanes should map to actor goals and
  repair paths.
- Software Architecture for Developers: make the cockpit a just-enough live
  architecture view.
- A Philosophy of Software Design: hide low-value complexity behind a small
  operator model.

VIO lens:

- workflow as a tree;
- progressive disclosure;
- visible enough for a collaborator to help;
- validate one thin path before broadening;
- classify context before acting.

Research lens:

- Shift-Up: executable guardrails beat narrative confidence.
- Skill-RAG: classify failure before retrying.
- HiveMind: provider timeouts and contention need visible state.
- ISO-Bench: status must link to artifacts, not just claims.

## Phase 26: Cockpit Operator Question Contract

Goal: define exactly what Cockpit 2.0 must answer and what each answer means.

Operator questions:

1. What is the model doing right now?
2. What are we trying to complete?
3. What does completing it unlock?
4. What is blocked or risky?
5. Which agents were used and what did each do?
6. What is Codex doing or what did Codex conclude?
7. What evidence/artifacts were produced?
8. What should happen next?

Work Claude should do:

- Read the current cockpit scripts.
- Map current panes to the eight operator questions.
- Mark each question as answered, partially answered, or missing.
- Define status vocabulary and freshness rules.
- Produce a behavior/use-case contract for the cockpit.
