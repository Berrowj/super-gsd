## Phase 128 — Stage Pipeline Data Model

**Goal:** Add a deterministic stage-pipeline data structure to the cockpit `--json` output describing which of 6 named stages the active phase is currently in, who owns it, time-in-stage, SLA window, and any blocker flag. Foundation for P129-P132.

**Why this first:** Every downstream phase consumes this. P129 renders it in Band 2. P130 references it in rationale. P132 streams it via SSE. Without it the downstream surfaces have nothing to bind to.

**5 stages** (operator decision 2026-05-24 — Q-D answered: dropped `discuss` because auto-mode synthesizes CONTEXT without an interactive discuss step):
1. `research` — owner: codex/xhigh — SLA: 30 min
2. `vtp-enrich` — owner: vtp-enrich — SLA: 5 min
3. `plan` — owner: codex/xhigh — SLA: 20 min
4. `execute` — owner: codex/xhigh — SLA: 90 min
5. `verify` — owner: codex/xhigh — SLA: 15 min

CONTEXT.md is now a **phase precondition** (must exist before pipeline starts), not a stage marker. In auto-mode the orchestrator synthesizes it; in interactive mode the operator authors it.

**Stage detection algorithm:** scan the phase directory for canonical artifact files. Each artifact maps to a stage's completion:
- `RESEARCH.md` exists → `research` ✓
- `VTP-ENRICHMENT.md` exists (or workflow toggle off) → `vtp-enrich` ✓
- `*-PLAN-LOCKED.md` exists → `plan` ✓
- last commit affects source under `super-gsd/` since `phase_start_ref` → `execute` ✓ (in progress while diff growing)
- `VERIFICATION.md` exists AND verdict=PASS → `verify` ✓

The first stage without its artifact is `active`. Stages after `active` are `pending`. If any blocker is recorded in STATE.md frontmatter or any gate has `RED` status, the active stage flips to `blocked`.

```javascript
const fs = require('fs');
const path = require('path');

function stageArtifactPresent(phaseDir, stage) {
  if (!phaseDir) return false;
  try {
    const entries = fs.readdirSync(phaseDir);
    const pattern = stage.artifact_glob;
    if (!pattern.includes('*')) return entries.includes(pattern);
    const re = new RegExp('^' + pattern.replace(/\*/g, '.*') + '$');
    return entries.some((e) => re.test(e));
  } catch (_err) { return false; }
}

function computeStagePipeline(input) {
  const phaseDir = input && input.phase_dir;
  const vtpEnabled = input && input.vtp_enabled !== false;
  const blocker = (input && input.blocker) || null;
  const stages = STAGES.map((stage) => {
    const isVtpSkipped = stage.name === 'vtp-enrich' && !vtpEnabled;
    const done = isVtpSkipped || stageArtifactPresent(phaseDir, stage);
    return { name: stage.name, owner: stage.owner, sla_minutes: stage.sla_minutes, status: done ? 'done' : 'pending' };
  });
  let activeIndex = stages.findIndex((s) => s.status === 'pending');
  if (activeIndex >= 0) {
    stages[activeIndex].status = blocker ? 'blocked' : 'active';
  }
  return { stages, active_index: activeIndex, blocker };
}

module.exports = { STAGES, computeStagePipeline, stageArtifactPresent };
```
