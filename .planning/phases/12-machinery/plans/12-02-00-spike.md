## Spike Design

Three trivial parallel Bash commands dispatched in one message with
`run_in_background: true`. Each command calls `date -u` and echoes a
named marker. All three dispatches were issued in the **same** tool-call
message (tool call IDs: `toolu_013jQXqVccartsFNdiT1pkfJ`,
`toolu_017aSKTfiTABHer3ntD5uB4Q`, `toolu_01DM9GxBateFZrHWv9XmhPnT`).

Workload: read-only (`date` + `echo`). No file writes. No orchestrator
code touched. Pure discovery.

The spike used Bash `run_in_background: true` as the closest available
proxy for `Agent(... run_in_background: true ...)`. Both are dispatched
through the same Claude Code task harness. The concurrency semantics of
the harness are the same regardless of whether the sub-process is a shell
command or a sub-agent.

| A        | bj5q8u8h3     | 2026-04-22T18:35:22.828Z     | Yes                    |
| B        | bpklg3yzr     | 2026-04-22T18:35:23.492Z     | Yes                    |
| C        | bnyfuoysz     | 2026-04-22T18:35:23.494Z     | Yes                    |

**Harvest read timestamp:** 2026-04-22T18:35:28.691Z
(all three tasks already completed at this point)

**Start delta between A and C:** 666 ms
(~22.828 vs ~23.494 — both started BEFORE A had time to finish)

**Concurrency verdict:** The harness started A, B, and C as overlapping
concurrent processes. A started at 22.828Z; B started at 23.492Z (664ms
after A) and C started 2ms after B — demonstrating that B and C were
dispatched while A was still running. A serial harness would have waited
for A to complete before starting B (total elapsed would be ~3× single-
task time). Instead, all three were active within a 666ms window and all
completed before the 28.691Z harvest read — consistent with parallel
execution.

---

## Decision

PARALLEL_CONFIRMED

The Claude Code task harness supports genuine concurrent fan-out when
background-dispatching multiple tasks in the same message. All three
dispatches received background IDs simultaneously, started within 666ms of
each other, and completed before a single subsequent read — behaviour
consistent with parallel execution, not serial.

## Impact on 12-02-01/03

**12-02-01 (dispatch-planner.cjs):** Implement the full Kahn topo-sort DAG
algorithm as designed. The `serial: false` flag in a wave is meaningful at
runtime — when it fires, the executor will genuinely fan out concurrent
Agent() dispatches.

**12-02-03 (SKILL.md integration):** The parallel branch (`run_in_background:
true` fan-out + await-all) should be authored as a **live code path**, not
a commented-out or advisory stub. The spike confirms the runtime will
execute it concurrently. Prose in the dispatch rule should present the
parallel branch as the primary path for disjoint waves, with the serial
branch as the guard for file-conflict or explicit-dependency cases.
