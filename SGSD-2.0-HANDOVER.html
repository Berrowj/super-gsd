01 · Executive Summary

SGSD 2.0 turns Claude Code into a disciplined delivery team. An Opus-driven orchestrator runs a thirteen-step loop, delegates to Haiku-classified sub-agents, gates every step against an empirically-tuned YAML registry, and couples the whole thing to a git-native memory tier. v1.2 Evidence-First Sharpening upgrades every surface from prose convention to declarative resource.

ELI5 — WHAT IS THIS THING?

You tell Claude Code to build software. The old way: it tries its best. The SGSD way: it follows a recipe. The recipe is written in YAML (not vibes). It commits after every small step (so you can undo). It runs a code reviewer before declaring done (so it doesn't lie to you about quality). And it remembers things across sessions in a folder you can actually read. SGSD 2.0 is the recipe book, the reviewer, and the filing cabinet — all wired together so Claude doesn't drift, doesn't hallucinate, and doesn't ship slop.

Headline shipments in v1.2

  • Phase 11 — Plan Schema v2. Canonical YAML-frontmatter plan format with required fields, self-healing validator, boot-hash drift check.
  • Phase 9 — Evidence. Retrospective audit of an external project's 147-phase review. 4-bucket classification of 10 findings and a 9-gate bypass audit with explicit token-cost bounds (18,940 upper / 9,340 lower).
  • Phase 10 — Gate Policy. 9 orchestrator quality gates become a YAML registry (super-gsd/registry/gates.yaml), shipped with a typed predicate evaluator and 9 integration sites wired into the orchestrator skill.
  • Phase 12 — Machinery. Per-plan classifier cache (4× token savings on homogeneous phases), DAG-based parallel dispatch, adversarial verifier sampling, mechanical 85% context-emergency halt.
  • Phase 13 — Governance. Deliberation board becomes a registered resource. Confidence-weighted vote synthesis. New /sgsd-complete-milestone skill with bidirectional VTP integration — milestones ingest prior research as enrichment, publish themselves back as Milestone-classified research artifacts.

Why this matters

Before SGSD 2.0, gate enforcement lived in prose inside a skill file. Any gate could be silently skipped and nobody would notice. Plans were free-form markdown — schema violations only showed at execution time. Memory was a dead MCP reference that was never actually installed. Dispatch logic was narrative, not declarative.

After v1.2: every gate is a YAML row with an empirical trigger. Every plan passes a mechanical validator before the executor sees it. Memory is a git-native filesystem tier with sgsd-recall as the callable interface. Dispatch rules are first-match predicates the orchestrator can audit and explain.

02 · The Upgrade Story — GSD → SGSD 2.0

GSD gave you an orchestrator. SGSD 2.0 gives you a measured orchestrator with a nervous system, a memory, and a board of directors.

GSD — the base framework

Pipeline with specialist agents

The original "Get Shit Done" framework shipped the plan-phase / execute-phase pipeline. Phases move through discuss → research → plan → plan-check → execute → verify. Each plan is a markdown file with inline tasks. Output: atomic commits.

  • Skill-driven workflows (/gsd-discuss-phase, /gsd-plan-phase)
  • Plan-checker as a verification gate before execution
  • Verifier as a goal-backward audit after execution
  • Model routing defaults (Haiku classify, Sonnet execute, Opus orchestrate)

What GSD doesn't solve: prose-based gate enforcement, free-form plan shape, no mechanical schema validation, no empirical keep/kill for quality gates, no cross-session memory.

SGSD 2.0 — the upgrade

Declarative substrate + nervous system

Keeps the GSD pipeline. Adds a nervous system and a declarative substrate. Everything that was prose becomes YAML. Every gate has an empirical trigger. Memory is first-class. The board of deliberators is a registered resource.

  • YAML registries: gates.yaml, board-members.yaml, agents.yaml, plan-schema-v2.json, decisions.yaml
  • Memory tier at .planning/memory/ with 8-folder taxonomy (DLB-01)
  • INTENT injection (DLB-03): milestone outcome injected into every dispatch prompt
  • MUDA waste audit (DLB-02) runs at phase close, detect-and-record
  • Adversarial verifier sampling catches silent PASS drift
  • Bidirectional VTP integration at milestone close

THE ONE-LINE DIFFERENCE

GSD runs the pipeline. SGSD 2.0 runs the pipeline and measures it, gates it, remembers it, reflects on it, and publishes the result.

ELI5 — WHY SEVEN LAYERS?

Think of a restaurant. Layer 1 is the customer ordering. Layer 2 is the menu. Layer 3 is the head chef — reads orders, decides who cooks what, but doesn't touch pans. Layer 4 is the cooks — each one does one dish really well. Layer 5a is the recipe book (YAML) — no cook invents a dish, they read the recipe. Layer 5b is the pantry — ingredients organised by category. Layer 6 is the order-ticket system — every dish logged. Layer 7 is the ledger — every completed order a receipt that can never be rewritten.

04 · The Autonomous Loop

One iteration = one dispatched agent + one atomic commit + one state update. Thirteen steps. Runs until an exit condition fires.

THE 13-STEP LOOP · ORCHESTRATOR · OPUS
STEP 01

Read State

Frontmatter only — 30 lines. milestone · phase · plan · status.

STEP 02

Classify (Haiku)

Returns complexity · model · atc_tier · deliberate. v2 plans: cache hit per Phase 12.

STEP 03

Deliberation Gate

If classifier.deliberate AND interactive → route to /sgsd-deliberate.

STEP 04

Select Context (Haiku)

Picks sgsd-recall queries from task keywords. Target: <100 tokens overhead.

STEP 05

sgsd-recall

Queries .planning/memory/. Injects top-3 matches as prompt context.

STEP 5.5

INTENT Injection (DLB-03)

Prepends outcome_delivered from milestones/{ver}/INTENT.md to every sub-agent prompt.

STEP 06

Determine Dispatch — First-Match Rules (Rule 0 → 6.7)

Readiness  ·  researcher  ·  planner  ·  plan-checker  ·  executor  ·  verifier  ·  ATC gate  ·  MUDA audit  ·  browser verify  ·  milestone close.

STEP 6.5

Phase ATC Gate

Once per phase, post-verifier. Haiku classifies tier → Sonnet runs ATC 7-step + 10-point anti-slop.

STEP 6.55

MUDA Audit (DLB-02)

Gate: ≥4 files OR ≥100 lines. Detect-and-record, never blocks.

STEP 6.6

Browser Verify

Only if frontend files touched. Ground-truth tool verdict — not prose.

STEP 6.7 · PHASE 13 SHIPMENT

Milestone Auto-Close

All milestone phases [x] in ROADMAP? → auto-dispatch sgsd-complete-milestone. No operator prompt. Idempotent; safe on resume.

STEP 07

Compose Prompt

XML plan + surgical constraint header + recall results. Target: <1,500 tokens.

STEP 08

Dispatch Sub-Agent

TaskCreate → Agent() → TaskUpdate. Every dispatch wrapped (non-negotiable).

STEP 09

Process Report

Parse 6 sections. 300-word max. BLOCKERS section non-empty → EXIT.

STEP 9.5

Per-Dispatch ATC

FULL tier + code files only. Skip LITE / SKIP tiers.

STEP 10

Curate Learnings

sgsd-curate new patterns / scripts / error-rules.

STEP 11

Update State

STATE.md · ROADMAP.md · token-log.jsonl append.

STEP 12

Atomic Git Commit

Never batch. Never skip. Never amend. Format: feat({phase-plan}): {ONE_LINER from agent report}.

STEP 13

Loop

Read STATE.md again. The Read tool call chains the next iteration. Text-only response = loop dies.

The golden rule

TEXT-ONLY = LOOP DIES

Every response from the orchestrator MUST include at least one tool call. A text-only response ends the session. The loop continues because the tail of every iteration pairs a status message with a Read STATE.md call. Exit conditions (the only 4 valid ones) explicitly break this contract:

(1) all phases complete · (2) context >70% → write checkpoint, then stop · (3) blocker requiring human input · (4) user says stop/pause.

05 · Dispatch Rules — First-Match Tree

Step 6 asks one question at a time, top to bottom. The first rule whose condition is TRUE wins. That's the dispatch.

Rule 0
Milestone entered without MILESTONE-READINESS.md?
→ sgsd-milestone-readiness (Sonnet)
Rule 0.5
Readiness returned BLOCKED or PARTIAL?
→ pause, present fix list (fix / degraded / go-anyway)
Rule 1
Phase has no CONTEXT.md (not discussed)?
→ suggest /gsd-discuss-phase (human-in-loop)
Rule 2
Phase has CONTEXT but no RESEARCH.md?
→ gsd-phase-researcher (Opus)
Rule 3
Phase has RESEARCH but no PLAN.md files?
→ gsd-planner (Opus)
Rule 4
Plans exist but no PLAN-CHECK.md?
→ gsd-plan-checker (Sonnet)
Rule 4.5
About to make FIRST executor dispatch of a phase?
→ sgsd-phase-readiness re-probe (Haiku, fast)
Rule 5
Plans checked, pending executable tasks?
→ gsd-executor (Sonnet)
Rule 6
All plans executed, no verification yet?
→ gsd-verifier (Sonnet)
Rule 6.g
Verification passed?
→ Phase ATC · MUDA · Browser verify · Mark complete
Rule 6.h
Verification returned FAIL / PASS-WITH-GAPS?
→ gsd-planner --gaps (Sonnet)
Rule 6.7
Phase complete AND all milestone phases [x]?
→ auto-dispatch sgsd-complete-milestone (Phase 13)
Rule 9
All phases across all milestones complete
→ EXIT: "All phases done."

ELI5 — WHY FIRST-MATCH?

Imagine a triage nurse. Someone walks in. Rule 1: "Are they bleeding?" Yes → trauma. No? Rule 2: "Are they not breathing?" Yes → ICU. And so on. The nurse doesn't run all rules in parallel — they stop at the first YES because that's the most urgent thing right now. SGSD does the same: "Does this phase need to be discussed? Researched? Planned? Checked? Executed? Verified?" Whatever's most urgent gets the dispatch.

The only agent that holds session context

Returns { complexity, model, atc_tier, deliberate, reason } for a given goal. Drives model routing and ATC tier for the dispatch. Phase 12 added per-plan caching — classify once per v2 plan, reuse across N tasks.

Declares the 4 archetypes (Architect, Contrarian, Pragmatist, Moonshot) + CEO. Phase 13 flips board_version from v1-static to v2-runtime-resolved and adds the structured escalation policy:

  add_pragmatist:
    trigger: "any(m.role=='Contrarian' AND m.position=='OPPOSE' AND m.confidence>=4)"
    reason: execution-feasibility dissent
  add_moonshot:
    trigger: "count(unique(m.position))==1 AND size(board)>=2"
    reason: consensus-risk (groupthink)

plan-schema-v2.json — Phase 11 shipment

Canonical schema every v2 plan validates against. Required top-level: schema_version, phase, plan, wave, depends_on, files_modified, tasks. Each task requires id, files_touched (≥1 entry), input_contract, output_contract, hypothesis, falsifier, stop_rule, verification_gates.

decisions.yaml + agents.yaml

Sibling registries. decisions.yaml catalogues DLB-NN memos with metadata. agents.yaml declares SGSD custom agents as first-class resources (per DLB-04 scoped-agent manifest).

WHY REGISTRIES BEAT PROSE

Prose: if an operator reads the skill and decides a gate doesn't apply, they can silently skip it. No audit trail. Registry: every dispatch reads the YAML, evaluates the trigger, logs the decision. If a gate should have fired but didn't, the edge-guard log catches it. Phase 10's empirical trigger column makes every enforcement choice defensible with data.

sgsd-recall

Read interface

Grep-based, case-insensitive, ranks by distinct-term count. sgsd-recall "query" --limit 5 returns top matches. No embeddings, no BM25 — defer until corpus ≥ 40 files (DLB-01 threshold).

sgsd-curate

Write interface

sgsd-curate --type pattern --slug my-pattern --summary "≤80 chars". Writes the typed .md file AND updates INDEX.md atomically — both land or neither.

What got migrated from .brv/ to .planning/memory/

v1.2 started with 30 files in a legacy .brv/context-tree/ directory (named after a dead external MCP that was never installed) plus 4 files in the non-git auto-memory. The sgsd-memory-migrate skill consolidated all 34 into the new v1.2 taxonomy and created a directory junction so Claude Code's auto-memory loading remained transparent. .brv/ was deleted entirely; .gitignore purged of dead references.

09 · Quality Gates — What Actually Stops Bad Code

SGSD doesn't trust a single gate. It stacks them. Gates at dispatch time, task time, plan time, phase time, and milestone time. Each catches something different.

Step 9.5 · Per-dispatch

Per-dispatch ATC

Fires only on FULL-tier dispatches where at least one code file changed. gsd-code-reviewer runs ATC 7-step + 10-point anti-slop on the single dispatch's diff. Writes a row to commit-reviews.jsonl.

Step 6.5 · Per-phase

Phase ATC

Runs ONCE per phase after the verifier passes. Reviews the entire phase as a coherent unit — cross-plan consistency, architectural coherence, unused code across plans. Complexity floor: ≥5 plans OR ≥500 lines = always FULL tier.

Step 6.55 · Per-phase

MUDA waste audit

Shell-script probes for 8 waste classes. Never blocks per DLB-02 — accumulates across milestones for kill-condition check at milestone close.

Plan-time

Nyquist validation

Every plan task must map to an automated verification OR a Wave 0 dependency. No "3 consecutive tasks without verify." Frontmatter flag nyquist_compliant: true only flips after planner confirms the map.

Plan-time

Plan schema v2 (Phase 11)

Mechanical JSON-schema validator. Plan file fails schema → planner gets --fix mode + 3 retries. Boot hash pin ensures the schema itself hasn't drifted since the skill was authored.

Step 9.5 · Post-verifier

Adversarial verifier (Phase 13)

20% of gsd-verifier PASSes get re-dispatched with a contrarian prompt header. Flip to FAIL: log VERIFIER_ADVERSARIAL_FLIP. PASS-WITH-GAPS: promote verdict. Rate tunable in config.atc.verifier_adversarial_rate.

Step 6.6 · Per-phase

Browser verify

Only runs when frontend files changed. Shells out to phase-verifier.mjs. Hard rules: no curl-only pass, no spinner-frozen screenshots, no empty-array as real data, every PROVEN verdict cites a ROADMAP success criterion.

Run-time

Edge-guard log (Phase 10)

Every step transition writes a JSONL row with {from_step, to_step, expected_emits, actual_emits, missing_emits, resolution}. If a gate should have fired but didn't, resolution: halt fires per the escalation field in gates.yaml.

Cold start

Boot hash drift (Phase 11)

Orchestrator re-hashes plan-schema-v2.json and compares to pinned schema_v2_hash in config.json. Drift → halt with operator action required. Prevents silent schema changes between sessions.

10 · Stopping Slop & Hallucination

Slop is the biggest risk in autonomous coding. SGSD 2.0 stacks six mechanisms against it — each catches a different failure mode.

01 · Pre-dispatch

The Surgical Constraint Header

Injected verbatim into every executor prompt (Step 7). Tells the agent: every changed line must trace to a task in this wave's plan. Orphan edits are DEVIATIONS. Match existing style. Don't delete pre-existing dead code. Remove only imports/vars YOUR changes made unused.

Catches: "while I'm here" refactors, unrelated formatting passes, scope creep inside a narrow task.

02 · Phase + Dispatch

The 10-Point Anti-Slop Checklist

Run at phase-level ATC (Step 6.5) and per-dispatch ATC (Step 9.5). Checks: every new function has a caller, every import used, every parameter read, could this be less code, are new abstractions justified, does existing code do 80%, would a senior engineer mass-delete this, ΔComplexity ≤ 0, any "just in case" additions, does this commit do ONE thing.

Catches: YAGNI violations, orphan functions, gratuitous abstractions.

03 · Pre-execution

The Plan-Checker (Sonnet)

Before any executor runs, the plan-checker reads all plan files and answers: does the union of these plans achieve the phase goal? Are tasks specific enough? Wave dependencies correct? Locked decisions honored? Outputs PASS / PASS-WITH-NOTES / FAIL with findings.

Catches: "this plan won't actually build what the roadmap promised."

04 · Post-dispatch

Structured Report (300-word max)

Every agent returns EXACTLY six sections: FILES_CHANGED, VERIFICATION, DEVIATIONS, BLOCKERS, SCRIPTS_CREATED, ONE_LINER. Missing section = logged; over 300 words = logged. Any claim unbacked by a FILES_CHANGED entry can't become a commit.

Catches: "I verified it" without evidence, hallucinated PASS without a cmd→exit line.

05 · Per-phase

Mechanical Verifiers

Phases 9, 10, 12, 13 each ship a verify.mjs with 7–16 hard invariants. Example: "findings_detail.length === 10 AND bucket sum equals headline." Hand-edit the YAML to break the math → verifier exits non-zero. Phase ATC verdict keys off this.

Catches: data tampering, arithmetic drift, documentation claiming one thing while artifacts show another.

06 · Post-verifier · Phase 13

Adversarial Verifier Sampling

After gsd-verifier returns PASS, 20% of the time re-dispatches it with a contrarian prompt: "Challenge the PASS. What are the top 3 ways this phase might silently fail?" Challenger flips → escalate. Challenger finds gaps → promote to PASS-WITH-GAPS.

Catches: primary verifier missed a cross-plan integration gap, assumption baked into plan contracts never proven in execution.

ELI5 — WHY STACK SIX GATES?

Swiss cheese model. One slice of cheese has holes — bad code can slip through. Stack six slices, each with different holes, and something has to slip through ALL the holes at once to escape. The plan-checker catches things before execution. The surgical constraint catches things during execution. The per-dispatch ATC catches things right after a dispatch. The phase ATC catches things at phase close. The verifier catches goal drift. The adversarial sampling catches verifier blind spots. For a defect to ship, it has to be invisible to all six — statistically, almost impossible.

11 · Drift Prevention

Drift is when an agent slowly forgets the goal. SGSD 2.0 fights drift with structural injection, not prompt discipline.

The INTENT injection pattern (DLB-03)

Every milestone has an INTENT.md with a single-line outcome_delivered field (≤120 characters). Before any executor / researcher / planner / verifier dispatch, the orchestrator prepends this block:

<intent milestone="v1.2">
Operators run autonomous phases with empirically-gated ATC gates and v2-schema plans.
</intent>

Every sub-agent sees this in its prompt header. The model's context window IS the enforcement — no regex presence check, no NL scoring gate. Shallow outcome strings are caught at milestone close by sgsd-intent-check.sh: it counts whether the injected text is referenced in executor deviations / verifier reports. Coverage <50% = author-discipline intervention.

The edge-guard log

Phase 10 introduced edge-guard.cjs. Every step transition in the orchestrator loop writes one JSONL row:

{
  "ts": "2026-04-22T18:00:00Z",
  "phase": 12,
  "plan": "12-03",
  "from_step": 9,
  "to_step": 9.5,
  "gate": "per-dispatch-ATC",
  "expected_emits": [".planning/phases/12/commit-reviews.jsonl"],
  "actual_emits": [".planning/phases/12/commit-reviews.jsonl"],
  "missing_emits": [],
  "resolution": "pass"
}

If missing_emits is non-empty AND the gate's escalation field in gates.yaml is halt, the orchestrator writes a checkpoint and exits. Otherwise resolution: log-only. Over time this log is the authoritative record of gate firings — the milestone-close MUDA recurrence check reads it.

Schema drift protection

Phase 11 pinned the hash of plan-schema-v2.json in config.json (schema_v2_hash). On every cold start, the orchestrator re-computes the hash. Mismatch = halt with operator action required. Catches the case where an auto-update overwrites the schema without tests rerunning.

The 85% context emergency halt (Phase 12 MACH-03)

Primary checkpoint trigger: (phase_boundary OR plan_boundary) AND context > 70%. Emergency override: context ≥ 85% forces checkpoint mid-task. Catches runaway context growth. Logged as CHECKPOINT_EMERGENCY in DEVIATIONS. If >10% of a milestone's checkpoints are emergency halts, flag as plan-decomposition issue.

Why bidirectional VTP matters

A closed milestone isn't a one-way artifact. Ingest means the summary doc includes a "Connections" section — prior Milestone artifacts the skill pulled from VTP that are semantically related. Gives the current milestone a knowledge-graph anchor. Publish means the summary becomes a VTP Milestone artifact itself, queryable by future milestones in future projects. The knowledge graph grows one milestone at a time.

Idempotency

The skill checks for existing milestones/{version}/SUMMARY.md before doing anything. If found: no-op PASS. Safe on resume — orchestrator can re-trigger at any point without duplicating work.

Trigger

Outcome

Outcome

17 · Deliberation Memos — The Strategic Bedrock

Before any v1.2 phase started, the board deliberated six strategic positions. Every phase references these. Every implementation honours them.

DLB-01

Memory Topology

Decision: Ship a git-native filesystem memory tier as the SGSD-global layer. No new MCP server. No cross-project extension. No BM25 ranking until measured need. 12 curated files → INDEX.md catalog → thin sgsd-recall grep wrapper. Orchestrator injects retrieved content at prompt-composition time.

Where it shows up: the entire memory system. Later evolved via sgsd-memory-migrate to the v1.2 8-folder taxonomy at .planning/memory/.

DLB-02

MUDA Learning Loop — Write-Path-First with Kill Condition

Decision: Narrow write path only + 3 targeted watchdog probes (haiku-fails, narrative staleness, git-spawn rate). No seed library, no two-tier promotion. Accept explicit kill condition: if no waste class recurs across 2 milestones, abandon the MUDA skill.

Where it shows up: Step 6.55 MUDA audit. Phase 10 + 12's WASTE.md. sgsd-muda-recurrence at milestone close.

DLB-03

Intent Continuity — Structural Injection, Not Presence Checks

Decision: 3-part minimal intervention. Christopher Alexander / Commander's Intent / Hoshin Kanri mapped onto SGSD primitives. The LLM context window IS the enforcement — no regex presence check, no NL scoring gate.

Where it shows up: Step 5.5 INTENT injection. Every dispatch prompt carries the milestone's outcome_delivered. Logs to intent-log.jsonl. Coverage check at milestone close.

DLB-04

Self-Evolving Resource Substrate — Narrow Trajectory-Distillation Synthesis

Decision: Minimum-viable resource manifest + operator-gated propose→commit loop + trajectory-distillation at milestone close with triple hallucination gate + AGP-vocabulary borrow without schema conformance. Narrow adoption — not full RSPL/SEPL build.

Where it shows up: agents.yaml manifest. sgsd-sepl skill. trajectory/ subtree in memory. sgsd-distill at milestone close.

DLB-05

VTP-Audit Sharpening — Narrow Synthesis with SPEC-NOW Retype

Decision: Soft-warn budget logging on /sgsd-deliberate; metric-only conformance logging at phase close; 2 additional MUDA probes (extra-processing + inventory); adopt Moonshot's refined retype as SPEC-NOW — document Process Mining's 7 anomaly patterns as DLB-02 deferred read-path spec.

Where it shows up: extended MUDA probes. Spec doc in trajectory/.

DLB-06

Central Distribution — Narrow Scope + Governance Floor

Decision: Narrow scope central distribution + unanimous meta-decision: file DELIBERATION-FLOOR.md as a governance pre-check for future briefs. Catches the "briefs with missing context" failure mode.

Where it shows up: DELIBERATION-FLOOR.md as a /sgsd-deliberate precondition. Phase 13 GOV-03 decision-memo template requires ## Falsifier + ## Dead Ends sections.
