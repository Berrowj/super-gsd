01   Executive Summary

SGSD 2.0 turns Claude Code into a disciplined delivery team: an Opus-driven orchestrator running a thirteen-step loop, delegating to Haiku-classified sub-agents, gated by an empirically-tuned YAML registry, and coupled to a git-native memory tier. v1.2 Evidence-First Sharpening upgrades every one of those surfaces from prose convention to declarative resource.

ELI5 — WHAT IS THIS THING?

You tell Claude Code to build software. The old way: it tries its best. The SGSD way: it follows a recipe. The recipe is written in YAML (not vibes), it commits after every small step (so you can undo), it runs a code reviewer before declaring done (so it doesn't lie to you about quality), and it remembers things across sessions in a folder you can actually read (not a database you can't inspect). SGSD 2.0 is the recipe book, the reviewer, and the filing cabinet — all wired up so Claude doesn't drift, doesn't hallucinate, and doesn't ship slop.

Headline shipments in v1.2

  • Phase 9 — Evidence. Retrospective audit of an external project's 147-phase review. Produced a 4-bucket classification of 10 findings and a 9-gate bypass audit with explicit token-cost bounds (18,940 upper / 9,340 lower).
  • Phase 10 — Gate Policy. Turned 9 orchestrator quality gates into a YAML registry (super-gsd/registry/gates.yaml), shipped a typed predicate evaluator, and wired 9 integration sites in the orchestrator skill to read the registry at dispatch time.
  • Phase 11 — Plan Schema v2. Canonical YAML-frontmatter plan format with required fields, self-healing validator (planner auto-retries on schema failure), and a boot hash drift check.
  • Phase 12 — Machinery. Per-plan classifier cache (4× token savings on homogeneous phases), DAG-based parallel dispatch, adversarial verifier sampling, mechanical 85% context-emergency halt, and a bash installer script that closes the Phase 10 cross-repo core.cjs patch.
  • Phase 13 — Governance (planned, not yet executed). Makes the deliberation board a registered resource, introduces confidence-weighted vote synthesis, and ships a new /sgsd-complete-milestone skill with bidirectional VTP integration — milestones ingest prior research as enrichment, then publish themselves back as a Milestone-classified research artifact.

Why this matters

Before SGSD 2.0, gate enforcement lived in prose inside a skill file. Any gate could be silently skipped and nobody would notice. Plans were free-form markdown; schema violations only showed at execution time. Memory was a dead MCP reference (brv-query) that was never actually installed. The orchestrator's dispatch logic was narrative, not declarative. After v1.2: every gate is a YAML row with an empirical trigger, every plan passes a mechanical validator before the executor sees it, memory is a git-native filesystem tier with sgsd-recall as the callable interface, and dispatch rules are first-match predicates the orchestrator can audit and explain.

02   The Upgrade Story: GSD → SGSD 2.0

GSD gave you an orchestrator. SGSD 2.0 gives you a measured orchestrator with a nervous system, a memory, and a board of directors.

GSD (the base framework)

The original "Get Shit Done" framework shipped the plan-phase / execute-phase pipeline. Phases move through discuss → research → plan → plan-check → execute → verify. Agents are specialised (researcher, planner, plan-checker, executor, verifier). Each plan is a markdown file with inline tasks. Output is atomic commits.

  • Skill-driven workflows (/gsd-discuss-phase, /gsd-plan-phase, etc.)
  • Plan-checker as a verification gate before execution
  • Verifier as a goal-backward audit after execution
  • Model routing defaults (Haiku classify, Sonnet execute, Opus orchestrate)

What GSD doesn't solve: prose-based gate enforcement, free-form plan shape, no mechanical schema validation, no empirical keep/kill for quality gates, no cross-session memory.

SGSD 2.0 (the upgrade)

Keeps the GSD pipeline, adds a nervous system and a declarative substrate. Everything that was prose becomes YAML. Every gate has an empirical trigger. Memory is first-class. The board of deliberators is a registered resource with a runtime roster. Milestones close themselves via an auto-triggered skill.

  • YAML registries: gates.yaml, board-members.yaml, agents.yaml, plan-schema-v2.json, decisions.yaml
  • Memory tier at .planning/memory/ with 8-folder taxonomy (DLB-01)
  • Intent injection (DLB-03): milestone outcome injected into every dispatch prompt
  • MUDA waste audit (DLB-02) runs at phase close, detect-and-record
  • Adversarial verifier sampling catches silent PASS drift
  • Bidirectional VTP integration at milestone close

What SGSD 2.0 adds on top: evidence-gated enforcement, schema-enforced plans, cross-session memory, drift-resistant structural injection, and milestone-as-artifact closing.

THE ONE-LINE DIFFERENCE

GSD runs the pipeline. SGSD 2.0 runs the pipeline and measures it, gates it, remembers it, reflects on it, and publishes the result.

03   Architecture at a Glance

Seven layers. Operator at the top, git at the bottom. Everything in between is declarative resources the orchestrator reads at runtime.

ELI5 — WHY SEVEN LAYERS?

Think of a restaurant. Layer 1 is the customer ordering. Layer 2 is the menu (commands). Layer 3 is the head chef — reads orders, decides who cooks what, but doesn't actually touch pans. Layer 4 is the cooks — each one does one dish really well. Layer 5a is the recipe book (YAML) — no cook invents a dish; they read the recipe. Layer 5b is the pantry — ingredients from past meals, organised by category. Layer 6 is the order ticket system — every dish that leaves the kitchen is logged. Layer 7 is the ledger — every completed order is a receipt that can never be rewritten.

04   The Autonomous Loop

One loop iteration = one dispatched agent + one atomic commit + one state update. Thirteen steps. Runs until exit condition fires.

The golden rule

TEXT-ONLY = LOOP DIES

Every response from the orchestrator MUST include at least one tool call. A text-only response ends the session. The loop continues because the tail of every iteration pairs a status message with a Read STATE.md call. Exit conditions (the only 4 valid ones) explicitly break this contract: (1) all phases complete, (2) context >70% → write checkpoint then stop, (3) blocker requiring human input, (4) user says stop/pause.

05   Dispatch Rules — First-Match Tree

Step 6 asks one question at a time, top to bottom. The first rule whose condition is TRUE wins. That's the dispatch.

ELI5 — WHY FIRST-MATCH?

Imagine a triage nurse. Someone walks in. Rule 1: "Are they actively bleeding?" Yes → trauma. No? Rule 2: "Are they not breathing?" Yes → ICU. No? … and so on. Each rule is a specific emergency. The nurse doesn't run all the rules in parallel — they stop at the first YES because that's the most urgent thing right now. SGSD does the same: "Does this phase need to be discussed? Researched? Planned? Checked? Executed? Verified?" Whatever's most urgent gets the dispatch. The orchestrator never runs two rules at once.

06   The Agent Roster

Every agent is a narrow specialist. Same model family (Claude Opus/Sonnet/Haiku) but different prompts, different output contracts, different scopes. Each runs in its own context window.

The orchestrator (Layer 3)

sgsd-orchestrate (Opus)

The only agent that holds session context. Reads state, classifies, dispatches, processes reports, commits, loops. Never does the work itself — always delegates. Budget: ~1,350 tokens per iteration. Enters auto mode on "go" / "auto" / "continue" and exits only on the four valid conditions.

Classification & selection (Haiku — cheap, fast)

sgsd-classifier

Returns { complexity, model, atc_tier, deliberate, reason } for a given goal. Drives model routing and ATC tier for the unit. Phase 12 added per-plan caching — classify once per v2 plan, reuse across N tasks.

sgsd-context-selector

Picks sgsd-recall queries based on task keywords. Budget: ~100 tokens. Output feeds step 5 of the loop.

board-members.yaml — Phase 13 activation target

Declares the 4 archetypes (Architect, Contrarian, Pragmatist, Moonshot) + CEO. Phase 13 flips board_version from v1-static to v2-runtime-resolved and adds the structured escalation policy:

escalation_policy:
  add_pragmatist:
    trigger: "any(m.role=='Contrarian' AND m.position=='OPPOSE' AND m.confidence>=4)"
    reason: execution-feasibility dissent
  add_moonshot:
    trigger: "count(unique(m.position))==1 AND size(board)>=2"
    reason: consensus-risk (groupthink)

plan-schema-v2.json — Phase 11 shipment

Canonical schema every v2 plan validates against. Required: schema_version, phase, plan, wave, depends_on, files_modified, tasks array. Each task requires id, files_touched (≥1 entry), input_contract, output_contract, hypothesis, falsifier, stop_rule, verification_gates.

decisions.yaml + agents.yaml

Sibling registries. decisions.yaml catalogues DLB-NN memos with metadata; agents.yaml declares the SGSD custom agents as first-class resources (per DLB-04 scoped-agent manifest).

WHY REGISTRIES BEAT PROSE

Prose: if an operator reads the skill and decides a gate doesn't apply, they can silently skip it. No audit trail. Registry: every dispatch reads the YAML, evaluates the trigger, logs the decision. If a gate should have fired but didn't, the edge-guard log catches it. Phase 10's empirical trigger column makes every enforcement choice defensible with data.

08   Memory Topology (DLB-01)

Memory is a folder. No database, no MCP, no ranking infrastructure. Just git-tracked markdown files organised by semantic category, indexed by a catalog, queried by grep. Boring on purpose.

What got migrated from .brv/ to .planning/memory/

v1.2 started with 30 files in a legacy .brv/context-tree/ directory (named after a dead external MCP that was never installed) plus 4 files in the non-git auto-memory. The sgsd-memory-migrate skill consolidated all 34 into the new v1.2 taxonomy and created a directory junction so Claude Code's auto-memory loading remained transparent. The .brv/ directory was deleted entirely; .gitignore purged of dead references.

09   Quality Gates — What Actually Stops Bad Code

SGSD doesn't trust a single gate. It stacks them. Gates at dispatch time, at task time, at plan time, at phase time, and at milestone time. Each one catches something different.

Per-dispatch ATC (Step 9.5)

Fires only on FULL-tier dispatches where at least one code file changed. The gsd-code-reviewer runs ATC 7-step + 10-point anti-slop on the single dispatch's diff. Writes a JSONL row to .planning/phases/{N}/commit-reviews.jsonl.

Phase ATC (Step 6.5)

Runs ONCE per phase after the verifier passes. Reviews the entire phase as a coherent unit — cross-plan consistency, architectural coherence, unused code across plans. Complexity floor: ≥5 plans OR ≥500 lines = always FULL tier.

MUDA waste audit (Step 6.55)

Shell-script probes for 8 waste classes (defects, waiting, motion, extra-processing, inventory, transportation, overproduction, overprocessing). Never blocks per DLB-02 — accumulates across milestones for kill-condition.

Nyquist validation (plan-time)

Every plan task must map to an automated verification OR a Wave 0 dependency. No "3 consecutive tasks without verify." Frontmatter flag nyquist_compliant: true only flips after planner confirms the map.

Plan schema (v2, Phase 11)

Mechanical JSON-schema validator (validate.cjs). Plan file fails schema → planner gets --fix mode + 3 retries. Boot hash pin ensures the schema file itself hasn't drifted since the skill was authored.

Adversarial verifier (Step 9.5 post-verifier, Phase 13)

20% of gsd-verifier PASSes get re-dispatched with a contrarian prompt header. If challenger flips to FAIL: log VERIFIER_ADVERSARIAL_FLIP. If PASS-WITH-GAPS: promote verdict. Default rate in config.atc.verifier_adversarial_rate.

Browser verify (Step 6.6)

Only runs when frontend files changed. Shells out to phase-verifier.mjs. Hard rules: no curl-only pass, no spinner-frozen screenshots, no empty-array as real data, every PROVEN verdict cites a ROADMAP success criterion.

Edge-guard log (Phase 10)

Every step transition in the orchestrator writes a JSONL row with {from_step, to_step, expected_emits, actual_emits, missing_emits, resolution}. If a gate that should have fired didn't, resolution: halt fires per the escalation field in gates.yaml.

Boot hash drift check (Phase 11)

On cold start, orchestrator hashes plan-schema-v2.json and compares to the pinned schema_v2_hash in config.json. Drift → halt with operator action required. Prevents silent schema changes between sessions.

10   Stopping Slop & Hallucination

Slop is the biggest risk in autonomous coding. SGSD 2.0 stacks six mechanisms against it — each catches a different failure mode.

1 · The Surgical Constraint Header

Injected verbatim into every executor prompt (Step 7). Tells the agent: every changed line must trace to a task in this wave's plan. Orphan edits are DEVIATIONS. Match existing style. Don't delete pre-existing dead code. Remove only imports/vars YOUR changes made unused.

Catches: "while I'm here" refactors, unrelated formatting passes, scope creep inside a narrow task.

2 · The 10-Point Anti-Slop Checklist

Run at phase-level ATC (Step 6.5) and per-dispatch ATC (Step 9.5). Checks: every new function has a caller, every import is used, every parameter is read, could this be less code, are new abstractions justified, does existing code do 80% of this, would a senior engineer mass-delete this, ΔComplexity ≤ 0, any "just in case" additions, does this commit do ONE thing.

Catches: YAGNI violations, orphan functions, gratuitous abstractions.

3 · The Plan-Checker (Sonnet, Rule 4)

Before any executor runs, the plan-checker reads all plan files and answers: does the union of these plans achieve the phase goal? Are tasks specific enough to run without asking? Wave dependencies correct? Locked decisions honored? Outputs PASS / PASS-WITH-NOTES / FAIL with a findings list.

Catches: "this plan won't actually build what the roadmap promised."

4 · Structured Report Format (300-word max)

Every agent returns EXACTLY six sections: FILES_CHANGED, VERIFICATION, DEVIATIONS, BLOCKERS, SCRIPTS_CREATED, ONE_LINER. Missing section = logged; over 300 words = logged. The orchestrator parses machine-style, not prose. Any claim unbacked by a FILES_CHANGED entry can't be a commit.

Catches: "I verified it" without evidence, hallucinated PASS without a cmd→exit line.

5 · Mechanical Verifiers (per phase)

Phases 9, 10, 12, 13 each ship a verify.mjs with 7–16 hard invariants. Example Phase 10 invariant: "findings_detail.length === 10 AND bucket sum equals headline." If the YAML is hand-edited to break the math, the verifier exits non-zero. Phase ATC verdict keys off this.

Catches: data tampering, arithmetic drift, documentation that claims one thing while artifacts show another.

6 · Adversarial Verifier Sampling (Phase 13 GOV-04)

After gsd-verifier returns PASS, 20% of the time re-dispatches it with a contrarian prompt: "Challenge the PASS. What are the top 3 ways this phase might silently fail despite the PASS?" If challenger flips: escalate. If challenger finds gaps: promote to PASS-WITH-GAPS.

Catches: primary verifier missed a cross-plan integration gap, assumption baked into plan contracts that wasn't proven in execution.

How the mechanisms compose

ELI5 — WHY STACK SIX GATES?

Swiss cheese model. One slice of cheese has holes — bad code can slip through. Stack six slices of cheese, each with different holes, and something has to slip through ALL the holes at once to escape. The plan-checker catches things before execution. The surgical constraint catches things during execution. The per-dispatch ATC catches things right after a dispatch. The phase ATC catches things at phase close. The verifier catches goal drift. The adversarial sampling catches verifier blind spots. For a defect to ship, it has to be invisible to all six — statistically, almost impossible.

11   Drift Prevention

Drift is when an agent slowly forgets the goal. SGSD 2.0 fights drift with structural injection, not prompt discipline.

The INTENT injection pattern (DLB-03)

Every milestone has an INTENT.md with a single-line outcome_delivered field (≤120 characters). Before any executor / researcher / planner / verifier dispatch, the orchestrator prepends this block:

<intent milestone="v1.2">
Operators run autonomous phases with empirically-gated ATC gates and v2-schema plans.
</intent>

Every sub-agent sees this in its prompt header. The model's context window IS the enforcement — no regex presence check, no NL scoring gate. Shallow outcome strings are caught at milestone close by sgsd-intent-check.sh: it counts whether the injected text is referenced in executor deviations / verifier reports. Coverage <50% = author-discipline intervention.

The edge-guard log

Phase 10 introduced edge-guard.cjs. Every step transition in the orchestrator loop writes one JSONL row:

{
  "ts": "2026-04-22T18:00:00Z",
  "phase": 12,
  "plan": "12-03",
  "from_step": 9,
  "to_step": 9.5,
  "gate": "per-dispatch-ATC",
  "expected_emits": [".planning/phases/12/commit-reviews.jsonl"],
  "actual_emits": [".planning/phases/12/commit-reviews.jsonl"],
  "missing_emits": [],
  "resolution": "pass"
}

If missing_emits is non-empty AND the gate's escalation field in gates.yaml is halt, the orchestrator writes a checkpoint and exits. Otherwise resolution: log-only. Over time this log is the authoritative record of gate firings — the milestone-close MUDA recurrence check reads it.

Schema drift protection

Phase 11 pinned the hash of plan-schema-v2.json in config.json (schema_v2_hash). On every cold start, the orchestrator re-computes the hash. Mismatch = halt with operator action required. This catches the case where an auto-update overwrites the schema without tests rerunning.

The 85% context emergency halt (Phase 12 MACH-03)

Primary checkpoint trigger: (phase_boundary OR plan_boundary) AND context > 70%. Emergency override: context >= 85% forces checkpoint mid-task. Catches runaway context growth. Logged as CHECKPOINT_EMERGENCY in DEVIATIONS. If >10% of a milestone's checkpoints are emergency halts, flag as plan-decomposition issue (plans were too long).

13   Execution Pipeline — Every Branch, Every Handover

One wave at a time. Within a wave: parallel if the DAG allows (Phase 12 MACH-02). After each wave: full-suite verify. After last wave: the big phase-close cascade.

The per-dispatch report contract

Every gsd-executor return has EXACTLY this shape:

FILES_CHANGED: path (created|modified)     # one per line
VERIFICATION: `cmd` → exit N ✓|✗            # one per verification_gate from plan
DEVIATIONS: [Rule N] description | none
BLOCKERS: description | none
SCRIPTS_CREATED: path | purpose | interface | none
ONE_LINER: substantive summary for commit message

No preamble. No summary. 300 words max. The orchestrator parses this mechanically — any missing section is logged and treated as empty. Any BLOCKER triggers Exit #3 (halt with human judgement required).

Wave execution in practice (Phase 12 PARALLEL_CONFIRMED spike)

Phase 12's first executor task was a live spike to prove Agent(run_in_background: true) actually runs concurrently in Claude Code. Result: 3 background dispatches started within 666ms of each other, completed before harvest read. This validates MACH-02 DAG-based parallel dispatch — Wave 1 plans with disjoint files_modified lists truly run in parallel, not serialized.

14   Milestone Close — sgsd-complete-milestone (Phase 13 shipment)

Auto-triggered by the orchestrator when the last phase of a milestone shows [x] in the roadmap. An 8-step workflow with bidirectional VTP integration. No operator prompt required.

Why bidirectional VTP matters

A closed milestone isn't a one-way artifact. Ingest means the summary doc includes "Connections" — prior Milestone artifacts the skill pulled from VTP that are semantically related. This gives the current milestone a knowledge graph anchor. Publish means the summary becomes a VTP Milestone artifact itself, queryable by future milestones in future projects. Knowledge graph grows one milestone at a time.

Idempotency

The skill checks for an existing milestones/{version}/SUMMARY.md before doing anything. If found: no-op PASS. This makes resume-after-checkpoint safe — the orchestrator can re-trigger at any point without duplicating work.

17   Deliberation Memos — The Strategic Bedrock

Before any v1.2 phase started, the board deliberated six strategic positions. Every phase references these. Every implementation honours them.

DLB-01 — Memory Topology

Decision: Ship a git-native filesystem memory tier as the SGSD-global layer. No new MCP server. No cross-project extension. No BM25 ranking until measured need. 12 curated files in .brv/context-tree/ → INDEX.md catalog → thin sgsd-recall grep wrapper. Orchestrator injects retrieved content at prompt-composition time.

Where it shows up: entire memory system. Later evolved in Phase 12 via sgsd-memory-migrate to the v1.2 8-folder taxonomy at .planning/memory/.

DLB-02 — MUDA Learning Loop

Decision: Narrow write path only + 3 targeted watchdog probes (haiku-fails, narrative staleness, git-spawn rate). No seed library, no two-tier promotion, no token-audit fold. Accept explicit kill condition: if no waste class recurs across 2 milestones, abandon the MUDA skill and rely on probes alone.

Where it shows up: Step 6.55 MUDA audit. Phase 10 + 12's WASTE.md. sgsd-muda-recurrence at milestone close.

DLB-03 — Intent Continuity (Structural Injection)

Decision: 3-part minimal intervention. Christopher Alexander / Commander's Intent / Hoshin Kanri mapped onto SGSD primitives. The LLM context window IS the enforcement — no regex presence check, no NL scoring gate.

Where it shows up: Step 5.5 INTENT injection. Every dispatch prompt carries the milestone's outcome_delivered. Logs to intent-log.jsonl. Coverage check at milestone close.

DLB-04 — Self-Evolving Resource Substrate

Decision: Minimum-viable resource manifest + operator-gated propose→commit loop + trajectory-distillation at milestone close with triple hallucination gate + AGP-vocabulary borrow without schema conformance. Narrow adoption — not full RSPL/SEPL build.

Where it shows up: agents.yaml manifest. sgsd-sepl skill (operator-gated). trajectory/ subtree in memory. sgsd-distill at milestone close.

DLB-05 — VTP-Audit Sharpening (SPEC-NOW retype)

Decision: Soft-warn budget logging on /sgsd-deliberate; metric-only conformance logging at phase close; 2 additional MUDA write-path probes (extra-processing + inventory) with concrete measurable signals; adopt Moonshot's refined retype as SPEC-NOW — document Process Mining's 7 anomaly patterns as the DLB-02 deferred read-path algorithm spec, without activating it.

Where it shows up: extended MUDA probes (seen in Phase 10's audit: 5 probes including inventory). Spec doc in trajectory/.

DLB-06 — Central Distribution (Governance Floor)

Decision: Narrow scope central distribution + unanimous meta-decision: file DELIBERATION-FLOOR.md as a governance pre-check for future briefs. Catches the "briefs with missing context" failure mode the R2 Contrarian critique surfaced.
